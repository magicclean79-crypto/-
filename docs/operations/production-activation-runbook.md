# 운영 활성화 런북 (Production Activation Runbook)

> TASK-4401, Sprint 44 — CTO 정책 4401-⑤
>
> 준비 단계(`/admin/readiness`)는 **시작해도 되는가**에 답합니다.
> 이 문서는 그다음 — **시작한 다음 무엇을 어떤 순서로 하고, 잘못되면 어떻게
> 되돌리는가** — 에 답합니다.
>
> 살아 있는 상태는 `/admin/runbook` (또는 `GET /ops/runbook`)에서 봅니다.
> 이 문서와 화면은 **같은 단계 정의**(`packages/core/src/ops/activation-runbook.ts`)
> 를 씁니다 — 문서와 화면이 따로 놀면 둘 중 하나는 반드시 낡습니다.

## 체크리스트가 아니라 런북인 이유

체크리스트는 "했는가"만 묻습니다. 런북은 세 가지를 더 적습니다:

1. **되돌리는 법.** 되돌릴 수 없는 단계라면 되돌릴 수 없다고 적습니다.
   되돌리는 법이 안 적힌 단계는 **사고가 났을 때 그 자리에서 지어내게**
   됩니다.
2. **누가 하는가.** 사람이 줘야 하는 것과 우리가 하는 것이 섞이면 "왜 아직
   안 됐지"의 답이 매번 달라집니다.
3. **무엇이 증거인가.** 증거를 미리 적어 두지 않으면 나중에 "아마 됐을
   것"이 증거 자리에 들어옵니다.

## 순서

**되돌릴 수 없는 것을 뒤에** 뒀습니다. 앞은 전부 읽기·확인이고, 실제로
외부에 흔적이 남고 돈이 나가는 것은 5단계(스모크)부터입니다.

| # | 단계 | 담당 | 되돌리기 |
| --- | --- | --- | --- |
| 1 | 사전 점검 통과 | 시스템 | 바꾸는 것이 없음 |
| 2 | 실 Provider 자격 증명 주입 | **사람** | 환경변수를 비우고 재기동 |
| 3 | 공식 주소로 나가는 길 열기 | **사람** | 허용 규칙 되돌리기 |
| 4 | 운영 호스트 목록 확정 | **사람** | 목록은 언제든 수정 가능 |
| 5 | **실 호출 스모크 3종** | 시스템 | **되돌릴 수 없음** |
| 6 | **실 Provider 전환 검증** | 시스템 | 설정은 되돌릴 수 있으나 **나간 요청은 되돌릴 수 없음** |
| 7 | 전환 후 관측 창 유지 | 시스템 | 관측은 아무것도 바꾸지 않음 |
| 8 | 되돌리는 절차 확인 | **사람** | 이 단계 자체가 되돌리는 절차 |

### 1. 사전 점검 통과

```bash
API_BASE=https://<api-host> GATE_EMAIL=... GATE_PASSWORD=... \
  pnpm validation:preflight
```

`exit 0`이어야 다음으로 갑니다. `exit 2`는 **판정하지 못한 것**이며 통과가
아닙니다. **강제로 통과시키는 옵션은 없습니다**(정책 4101-⑥).

### 2~4. 사람이 주어야 하는 것

`docs/operations/validation-environment.md`에 항목별로 적었습니다. 요약하면
**Provider 자격 증명 · Network Allowlist · Validation Environment ·
Production Host Inventory** 넷이고, 넷 다 코드로 해결되지 않습니다.

### 5. 실 호출 스모크 3종 — 여기서부터 되돌릴 수 없습니다

```bash
curl -X POST https://<api-host>/ops/smoke   # ADMIN 인증 필요
```

- **이 단계부터 외부에 요청이 나가고 과금됩니다.** 중단은 할 수 있지만 이미
  나간 호출은 취소되지 않습니다.
- `stubbed`가 1건이라도 있으면 통과가 아닙니다 — 스텁 성공은 계약 확인이지
  연결 확인이 아닙니다.

### 6. 실 Provider 전환 검증

```bash
pnpm cutover   # exit 0이어야 전환이 끝난 것입니다
```

되돌리기: Provider 설정을 이전 값으로 되돌리고 재기동하면 **새 요청은**
스텁으로 갑니다. 전환 이후에 나간 요청은 되돌릴 수 없습니다.

### 7. 전환 후 관측 창

전환 직후의 "정상"은 **아직 아무것도 안 해 본 정상**입니다. KPI 스냅샷이
전환 전후로 각각 있어야 비교가 됩니다(스냅샷 두 점은 최소 20시간 떨어져
있어야 합니다 — 정책 4301-⑤).

이 창 동안 보는 것:

| 무엇 | 어디서 | 나쁘면 |
| --- | --- | --- |
| 실패율·지연 | `/admin/kpi` | 6단계 되돌리기 |
| 비용 | `/admin/costs` · `/ops/cost/projects` | 예산 경보가 먼저 울립니다 |
| 진단 | `/ops/diagnostics` | 실패 항목부터 |
| 방치 | `/ops/neglect` | 무시하려면 사유·담당자·검토일이 필요합니다 |

### 8. 되돌리는 절차 확인

최근 복구 리허설 기록이 있어야 하고, 그 절차가 이번 전환에도 적용되는지
사람이 확인합니다. **리허설 기록이 없는 것은 실패가 아니라 아직 안 한
것입니다** — 다만 그 상태로 6단계를 넘기지 않습니다.

## 사고가 났을 때

1. **먼저 되돌립니다.** 원인 분석은 되돌린 뒤에 합니다.
2. 장애 초안이 자동으로 만들어집니다(정책 3901-⑤) — **초안은 장애가
   아닙니다.** 확인하거나 사유와 함께 기각해 주세요.
3. 만료된 초안을 나중에 확인해도 **만료됐던 사실은 지워지지 않습니다**
   (정책 4101-④). 그 기록은 "잘 처리했다"가 아니라 "그만큼 늦게 알았다"는
   뜻입니다.

## 이 런북이 스스로 낡지 않게 하는 것

- 단계 정의는 코드에 있고 화면과 문서가 같은 것을 씁니다.
- 각 단계의 상태는 **이미 있는 판정을 인용**합니다 — 런북이 자기 판정을
  만들면 준비 화면과 다른 말을 하게 되고, 둘이 어긋나는 순간 사람은 둘 다
  안 믿습니다.
- 상태를 읽지 못한 단계는 `확인 못 함`이며 **통과로 세지 않습니다.**
