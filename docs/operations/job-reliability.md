# 작업 신뢰성 안내

> TASK-4603, Sprint 46 — 프로덕션 품질
>
> 예외 분류 · 로그 · 자동 복구 · 성능 계측을 **한자리에** 모은 층입니다.
> 기존 경로는 하나도 바뀌지 않았습니다 — 이 층은 그 위에 얹힙니다.

## 왜 층을 따로 뒀는가

타임아웃·재시도·체크포인트·계측을 호출 지점마다 손으로 붙이면 **붙이는 것을
잊은 경로가 생깁니다.** 그리고 그 경로는 잘 돌 때는 티가 안 나고 **사고가 난
날에만** 드러납니다. 한자리에 두면 잊을 자리가 없습니다.

## 실패 분류 (`classifyFailure`)

| 종류 | 뜻 | 다시 시도 |
| --- | --- | --- |
| `network` | 상대에 닿지 못함 | ✅ |
| `timeout` | 시간 안에 답이 없음 | ✅ |
| `throttled` | 상대가 429 | ✅ |
| `upstream` | 상대가 5xx | ✅ |
| `database` · `storage` | 우리 저장 계층 | ✅ |
| `rejected` (4xx) · `unauthorized` | 다시 보내도 같은 답 | ❌ |
| **`blocked`** | **우리가 막음(예산·게이트)** | ❌ |
| `unknown` | 모름 | ❌ |

**`unknown`은 재시도하지 않습니다.** 모르는 실패를 반복하면 어떤 실패인지
영영 모른 채로 돈만 씁니다.

### 우리가 막은 것을 상태 코드보다 먼저 봅니다

라이브에서 잡은 것: 예산 초과는 **HTTP 429**로 나갑니다(그 선택 자체는
옳습니다 — 클라이언트에게는 "지금은 안 된다"입니다). 그런데 상태 코드만
보면 `throttled`가 되어 **"잠시 후 다시 시도해 주세요"** 라고 말하게 됩니다.

예산은 기다린다고 열리지 않고, 재시도하면 **돈이 나가는 호출을 반복**합니다.
그래서 우리 문구(`예산을 초과` · `차단했습니다` · `강제로 여는 방법은
없습니다` …)를 **상태 코드보다 먼저** 봅니다. 상대 서비스의 429 본문에 이
말이 들어 있을 리 없습니다.

### 사용자 문장과 운영자 문장을 가릅니다

- **사용자**: "무엇을 하면 되는가". 원문·스택·주소를 넣지 않습니다 — 원문에
  무엇이 들어 있는지 우리가 미리 알 수 없습니다.
- **운영자**: "무엇이 일어났는가". 여기서는 뭉개지 않습니다.

## 로그

등급은 **넷뿐**입니다: `debug` · `info` · `warn` · `error`. 더 두면 아무도
기준을 못 지킵니다. 기본 최소 등급은 `info`이며 `LOG_LEVEL`로 바꿉니다
(알 수 없는 값은 기본값으로 되돌리되 **그 사실을 말합니다**).

한 줄의 맨 앞은 **작업 id**입니다 — 뒤에 두면 줄이 길어졌을 때 잘려서,
정작 묶어 보려고 만든 값이 안 보입니다.

### 비밀은 적기 전에 가립니다

로그는 가장 많이 복사되는 텍스트입니다 — 이슈에, 채팅에, 화면 캡처에.
`key` · `token` · `secret` · `password` · `authorization` · `cookie` ·
`webhook` · `url` 이 **이름에 들어간 값**은 `[가림]`으로 바뀝니다.

값의 모양으로 가리지 않는 이유: 새 Provider가 다른 모양의 키를 쓰는 날
조용히 새어 나갑니다.

## 자동 복구 (체크포인트)

단계가 끝날 때마다 체크포인트를 남기고, 이어할 때 **끝난 단계를 건너뜁니다.**

이어하기가 위험한 이유는 "이어한다"가 **하지 않은 일을 했다고 치는 것**과
종이 한 장 차이이기 때문입니다. 그래서:

| 규칙 | 왜 |
| --- | --- |
| **끝난 단계만** 건너뛴다 | 진행 중이던 단계가 어디까지 갔는지 우리는 모른다 |
| **순서대로만** 건너뛴다 | 5번이 끝났다고 3번을 건너뛰면 3번은 영영 안 한다 |
| 입력이 달라지면 처음부터 | 바뀐 입력에 옛 결과를 붙이면 그 결과는 어느 입력의 것도 아니다 |
| 24시간이 지나면 처음부터 | 그 사이에 무엇이 바뀌었는지 모른다 |
| **같은 행에 이어 쓴다** | 새 행을 만들면 "몇 번 만에 됐는가"가 흩어지고 앞의 시도가 없던 일이 된다 |

마지막 항목은 라이브에서 잡았습니다 — 첫 단계에서 죽은 작업을 이어했더니
새 행이 생기고 앞의 실패가 영영 `failed`로 남았습니다.

### 재시도

작업 재시도는 알림 재시도(TASK-1401, 4회)보다 **적은 3회**입니다.
2초 → 4초 → 8초(상한 30초).

> **돈이 나가는 재시도는 공짜가 아닙니다.** 알림을 네 번 보내는 것과 LLM을
> 네 번 부르는 것은 비용이 다릅니다.

`JOB_RETRY_MAX_ATTEMPTS`(1~5) · `JOB_RETRY_BASE_DELAY_MS` ·
`JOB_RETRY_MAX_DELAY_MS`로 바꿉니다. 상한을 둔 이유는, 없으면 누군가 100회를
적고 그 비용은 사고가 난 뒤에 알게 되기 때문입니다.

## 성능 계측

| 값 | 설명 |
| --- | --- |
| 단계별 시간 | 어디가 느린지 — "느리다"는 고칠 수 없고 "어디가"가 있어야 고친다 |
| 토큰 | **모르면 `null`이고 0으로 채우지 않는다** — 채우면 합계가 실제보다 작아지고 그 합계로 비용을 재면 청구서와 어긋난다 |
| `processHeapDeltaBytes` | **이 단계가 쓴 메모리가 아니다** (아래) |
| 전체 시간 | 처음부터 끝까지 |
| 안 잰 시간 | 전체 − 단계 합. **감추지 않는다** |

### 메모리를 이 작업의 것이라고 말하지 않습니다

`process.memoryUsage()`는 **프로세스 전체** 값입니다. 이 작업이 도는 동안
다른 요청 열 개가 같이 돌았다면 그 증가분은 이 작업의 것이 아닙니다.
"이 작업이 쓴 메모리 12MB"라고 적어 두면 아무도 그 사실을 다시 확인하지
않습니다.

그래서 이름을 `processHeapDeltaBytes`로 두었습니다. 그래도 남기는 이유는,
한 작업이 도는 동안 힙이 200MB 늘었다면 **그건 어느 작업의 것이든 봐야 할
신호**이기 때문입니다.

### 추세는 표본이 모자라면 판정하지 않습니다

한 번 느렸던 것을 "느린 단계"로 적으면 그날 네트워크가 흔들린 것이 **영구
결함으로 남습니다.** 최소 5건이며, 모자라면 `insufficient`입니다 —
**빠르다는 뜻이 아닙니다.** 평균이 아니라 **중앙값**으로 봅니다(한 번의 큰
값이 평균을 끌고 갑니다).

## 첫 대상 — 이미지 묶음 OCR

`POST /jobs/ocr-batch` (ADMIN · 한 번에 최대 50장 · **실 호출·과금**)

`OcrService.runOcr`을 **그대로 부릅니다.** 기존 `POST /images/:id/ocr`은
예전과 똑같이 동작합니다.

### 던지지 않았다고 성공이 아닙니다

`runOcr`은 Provider 실패를 기록하고 `status: "FAILED"`로 **돌려줍니다** —
한 장이 실패했다고 요청 전체를 500으로 만들지 않으려는 의도이고, 그 판단은
옳습니다. 그런데 그것을 그대로 성공으로 세면 **"3/3 끝냈습니다"라고 말하면서
한 장은 글자가 없는** 상태가 되고, 체크포인트가 그 장을 끝난 것으로 표시해
이어하기로도 다시 시도되지 않습니다(라이브에서 잡음).

그래서 결과의 `status`를 보고, 실패면 **기록된 사유를 분류**합니다:

- **공통 원인**(연결·시간 초과·상대 서버·정책) → **배치를 멈춥니다.**
  계속해 봐야 열 번 더 실패하고 그중 일부는 돈이 나갑니다.
- **이 한 장의 문제**(파일 없음·형식) → **건너뛰되 결과에 남깁니다.**
  한 장 때문에 나머지 아홉 장을 못 하면 배치의 의미가 없습니다.

건너뛴 것은 화면 문장에 그대로 나오고, **전부 건너뛰었으면** "결과를 얻은
항목이 하나도 없습니다"라고 말합니다 — 아무것도 못 얻은 실행이 성공으로
읽히면 안 됩니다.

## 전역 예외 필터

`HttpException`은 **그대로 통과합니다.** 지금까지 만든 400·403·404 응답의
본문과 상태 코드가 한 글자도 달라지지 않았습니다.

달라지는 것은 **분류되지 않은 오류 하나뿐**입니다:

```json
{
  "statusCode": 500,
  "message": "외부 서비스에 연결하지 못했습니다. 잠시 후 다시 시도해 주세요.",
  "error": "Internal Server Error",
  "requestId": "…"
}
```

`requestId`가 없으면 사용자는 "저 오류요"라고만 말할 수 있고, 그걸로는
아무도 못 찾습니다.

  못해** `unknown`이 되고 있었습니다 — Vision이 503을 내는데도 묶음이
  "성공"으로 끝났습니다. 이제 우리 문장이 담은 상태 코드를 되찾습니다.
- **자격 증명 실패는 한 건의 문제가 될 수 없습니다** — 이제 묶음을 멈춥니다.
