## 3. 변경 사항 (이번 보고 주기)

### TASK-2301 — Enterprise Deployment Governance

CTO 결정 2201-①~④가 이번 TASK의 범위였습니다.

주제는 **경계를 문서가 아니라 판정으로 만드는 것**입니다. "운영 담당자가
한다"고 적어 두는 것과, 하지 않았을 때 **배포가 막히는** 것은 다릅니다.
TASK-2201이 경계를 그었고, 이번에는 그 경계를 **지키지 않으면 드러나게**
만들었습니다.

**1. 스키마도 운영 담당자가 (결정 2201-①)**

저장소·IAM에 이어 DB 스키마까지 같은 경계를 적용했습니다.
`mayApplyMigrations`는 **어느 환경에서도 `false`** 입니다 — 개발에서도 기동이
스키마를 바꾸면 브랜치를 옮길 때마다 데이터가 조용히 달라집니다.

> **검증만 한다는 것은 검증이 실제로 작동해야 한다는 뜻입니다. 여기서 기존
> 결함을 발견했습니다.**
>
> `pendingMigrations`가 `_prisma_migrations`의 **실패 행만** 세고 있었습니다.
> 적용하지 않은 마이그레이션은 **실패 행조차 남기지 않으므로**, 운영 담당자가
> `migrate deploy`를 잊으면 `pendingMigrations: 0` — 즉 **"미적용 마이그레이션
> 없음"이라는 거짓 통과**가 나왔습니다. 결정 2201-①이 요구하는 "검증"이
> 정확히 이 경우를 잡아야 하는데, 잡지 못하고 있었습니다.
>
> 마이그레이션 **디렉터리와 적용 기록을 대조**하도록 바꿨습니다
> (`judgeMigrations`).

| 상황 | 판정 |
| --- | --- |
| 전부 적용 | 통과 |
| 미적용 존재 | **실패** — 이름을 나열하고 적용 주체를 밝힘 |
| 적용 중 실패·롤백 | **실패** — 스키마가 중간 상태 |
| 적용됐는데 코드에 없음 | **주의** — 되돌린 배포·브랜치 불일치 신호 |
| 목록·기록 중 하나라도 못 읽음 | 직접 확인 |

마지막에서 두 번째를 `주의`로 둔 이유는, 코드가 뒤로 간 것 자체는 사고가
아니지만 **조용히 지나가면 "왜 이 컬럼이 있지"를 나중에 아무도 설명할 수 없기**
때문입니다.

**2. 자동 복구를 만들지 않습니다 (결정 2201-②)**

원격 대조 실패는 **Critical Alert만** 냅니다. 자동으로 다시 올리면 두 가지가
위험합니다.

- 지금 로컬에 있는 덤프가 온전한지 확인하지 않은 채 원격을 덮어써,
  **틀린 사본을 더 확실하게** 만들 수 있습니다.
- 사라진 이유(수명 주기 정책·권한·사람의 삭제)를 모르는 채 다시 올리면
  같은 일이 반복됩니다.

**경보 문구에 수동 복구임과 절차 위치를 적었습니다** — 무엇을 해야 하는지
적지 않은 경보는 읽어도 할 일이 없습니다. DR 문서에 4단계 복구 절차를
넣었고, "2번(원인 파악)을 건너뛰고 3번만 하면 다음 주에 같은 경보가 온다"는
점을 명시했습니다.

대조 경로가 `putBackupObject`를 부르지 않음을 **소스 검사로 고정**했습니다.

**3. 우회 플래그를 두지 않습니다 (결정 2201-③)**

`STORAGE_PROVISIONING`을 추가하지 않고 정책은 `NODE_ENV`만 봅니다.
**설정해도 무시됨**을 테스트로 고정했습니다 — 하지 않기로 한 일은 코드에
흔적이 없어서, 나중에 누가 "편의를 위해" 되살려도 아무도 모릅니다.

**4. 운영 표준 배포 체크리스트 (결정 2201-④)**

다섯 항목을 배포 체크리스트로 **승격**했습니다.

| 항목 | id | 운영 배포 차단 |
| --- | --- | --- |
| 이미지 버킷 준비 | `bucket` | **예** |
| 저장소 접근 권한 (IAM) | `iam` | 아니오 |
| 이미지 버킷 버전 관리 | `versioning` | **꺼져 있을 때만** |
| 백업 버킷 준비·분리 | `backup-bucket` | **예** |
| 재해 복구 판정 | `readiness` | **예** |

- `iam`이 차단하지 않는 이유: 보호 상태를 **읽지 못해도 지금 서비스는 돕니다.**
  다만 조회 권한이 없다는 신호이므로 운영에서는 주의로 드러냅니다.
- `versioning`이 조회 불가일 때 차단하지 않는 이유: **모르는 것을 실패로
  단정하지 않습니다**(`직접 확인`).
- **복구 리허설은 배포 게이트에 들어오지 않습니다** (결정 1801-②) — 회귀
  테스트로 고정했습니다.

`docs/operations/deployment-checklist.md`를 **운영 표준 문서**로 신설했습니다.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 경계를 판정으로**:

```
NODE_ENV ─▶ resolveProvisioningPolicy
              ├─ mayCreateBucket      (운영 X)
              ├─ maySetPolicy         (운영 X)
              └─ mayApplyMigrations   (어느 환경에서도 X)   ← TASK-2301

prisma/migrations/*  ─┐
_prisma_migrations   ─┴─▶ judgeMigrations
                            ├─ 미적용 → fail (이름·주체 명시)
                            ├─ unknown → warn (스키마가 코드보다 앞섬)
                            └─ 못 읽음 → manual
                                  └─▶ 배포 체크리스트 `migrations` (차단)

버킷·IAM·버전 관리·백업 버킷·복구 판정
   └─▶ buildDeploymentChecklist (운영 표준 5항목, TASK-2301)
         └─▶ /health/ready · deployment-gate.mjs (exit 0/1/2)

원격 대조 실패 ─▶ Critical Alert (수동 복구 안내 포함)
                    └─ 자동 재업로드 경로 없음 (소스 검사로 고정)
```

① **애플리케이션이 인프라도 스키마도 바꾸지 않습니다.** 이제 경계가 셋
   (저장소·권한·스키마) 모두에 그어졌습니다.
② **검증이 실제로 작동하는지를 검증했습니다** — 이번 결함이 그 필요를
   보여줍니다. "검증만 한다"는 경계는 검증이 거짓 통과를 내면 무의미합니다.
③ **하지 않기로 한 것을 테스트로 남깁니다** — 우회 플래그, 자동 복구,
   배포 게이트에 넣지 않을 항목.
④ **운영 표준은 문서와 판정을 함께 둡니다** — 문서만 있으면 "확인했다고 치는"
   절차가 됩니다.

## 6. 데이터 모델

**이번 주기 마이그레이션 없음.**

스키마 거버넌스는 **기존 `_prisma_migrations`를 읽는 방식만 바꿨습니다** —
실패 행 개수에서 **적용된 이름 목록**으로. 검증을 위해 새 테이블을 만들면
그 테이블 자체가 마이그레이션이 되고, 검증 대상과 검증 수단이 뒤섞입니다.

라이브 검증용으로 만든 임시 마이그레이션
(`20260901000000_governance_probe`)은 **커밋에 포함하지 않았고** 적용 기록도
정리했습니다.

## 7. API 표면

**새 엔드포인트 없음.** 기존 `GET /health/ready`(ADMIN)가 확장됐습니다.

- `migrations` 추가 — `status` · `detail` · `pending[]` · `unknown[]` ·
  **`appliedBy`**(`operator` | `developer`)
- `pendingMigrations`의 **의미가 바뀌었습니다**: 실패 행 개수 → **실제 미적용
  건수**. 값의 타입은 같지만 뜻이 달라졌으므로, 이 값을 읽는 외부 모니터링이
  있다면 확인이 필요합니다
- 체크리스트에 **`bucket` · `iam` · `versioning` · `backup-bucket` ·
  `readiness`** 항목 추가
- `StorageService.bucketExists(bucket?)` 추가 (내부)
- 그 외 기존 API 계약 변경 없음

   (결정 2101-④). 그때까지 `versioning`이 운영 배포를 막습니다
7. **백업 성능 기준은 여전히 개발 규모에서만 검증됐습니다**
8. **복원 검증은 테이블 수만 봅니다** — 행 수·제약까지 보지 않습니다
9. **실 Provider 스모크는 여전히 미검증** — 샌드박스 차단 + 과금
10. **GitHub Actions 실제 실행은 확인하지 못했습니다** — 워크플로 순서는
    테스트로 고정했습니다
