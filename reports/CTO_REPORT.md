**질문 ②(공지가 밝힌 발효 시각을 예약에 자동으로 채울지)와 ③(최종 승인자를

**2. Provider별 공지 어댑터 (지시 2 — 결정 3301-⑤)**

한 주소가 모든 단가를 담으면 **그 주소 하나가 죽을 때 아무 단가도 대조하지
못합니다.** OpenAI 공지가 안 열린다는 이유로 Google 단가까지 확인을 못 하는 것은
사실과 맞지 않습니다.

```bash
PRICE_SOURCE_URL_OPENAI=https://openai.example/pricing.json
PRICE_SOURCE_FORMAT_OPENAI=flat        # acos | flat
PRICE_SOURCE_TOKEN_OPENAI=<이 소스에만 보낸다>
PRICE_SOURCE_URL_GOOGLE=https://google.example/pricing.json
PRICE_SOURCE_URL=<그대로 두면 default 소스로 계속 돈다>
```

- **따로 읽고 따로 판정합니다.** 소스별 상태·주소·형식이 화면과 응답에 남습니다.
- **전체 상태는 가장 나쁜 것을 따릅니다.** 셋 중 둘을 읽었다고 "정상"이라 하면
  못 읽은 하나가 다시 사라집니다 — `partial`을 따로 둔 것과 같은 이유이고,
  이번에는 그 단위가 **줄이 아니라 소스**입니다.
- **읽은 단가는 버리지 않습니다.** 한 곳이 죽었다고 나머지 대조를 멈추면 소스를
  나눈 이유가 없어집니다.
- **모르는 형식은 짐작해서 읽지 않습니다.** `PRICE_SOURCE_FORMAT_*`가 아는 값이
  아니면 그 소스를 **읽지 않고 사유를 남깁니다** — 잘못 읽은 단가는 못 읽은
  단가보다 위험합니다.
- **프로젝트별 공지는 거부합니다** — 정책 3301-④와 같은 이유입니다.
- 제안 근거에 **어느 공지가 알렸는지**(`sourceId`)가 남고, 실행 이력
  (`price_detection_runs`)도 **소스별로** 남습니다.

**3. 공지 실패 장기화 시 등급 승격 (지시 3 — 결정 3301-⑥)**

기본 24시간(`PRICE_SOURCE_ESCALATE_AFTER_MS`)을 넘겨 같은 공지를 못 읽고 있으면
`warning` → `critical`로 올라가고 문구에 **몇 시간째인지**가 붙습니다. 같은
warning이 반복되면 사람은 그것을 "원래 그런 경보"로 읽고, 그 순간 경보는 있는데
아무도 보지 않는 상태가 됩니다.

두 가지를 지켰습니다.

- **미구성은 승격하지 않습니다.** 아직 안 붙인 것은 시간이 지나도 실패가 되지
  않습니다 — 승격하면 "붙이지 않기로 한" 선택이 며칠 뒤 장애로 둔갑합니다.
- **시작 시각을 경보에서 세지 않습니다.** 경보의 `firstRaisedAt`은 "처음 본
  때"(해소된 사건까지 포함)를 뜻합니다(결정 2301-②가 그렇게 쓰고 있습니다).
  그것으로 세면 지난달에 한 번 실패하고 나았던 공지가 오늘 다시 실패하는 순간
  곧바로 critical이 됩니다. 그래서 **실행 이력에서 이어진 실패의 시작**을
  셉니다 — 중간에 한 번이라도 읽혔으면 거기서 끊습니다.

경보 키도 **소스별**(`price-source:openai`)입니다. 한 키로 묶으면 한 곳이 나아도
다른 곳의 실패가 그 뒤에 숨습니다.

**4. 실 Google Cloud Vision·LLM 운영 검증 (지시 4)**

`GET /ops/cutover` 신설. 연결 순서 판정(`/ops/providers`, TASK-2901)이 "어디까지
붙였는가"에 답한다면, 이 판정은 **"붙은 상대가 진짜인가"** 에 답합니다.

우리는 라이브 검증에서 계약 스텁을 씁니다. 스텁은 좋은 도구지만 **성공 기록이
남습니다.** 연결 순서 판정은 "성공 기록이 있으면 `connected`"이므로, 그 기록이
스텁을 상대로 만들어졌다면 화면은 **연결되지 않은 시스템을 연결됐다고
보고**합니다.

| 판정 | 뜻 |
| --- | --- |
| `verified` | 공식 주소로 최근 성공 기록이 있다 |
| `not-production` | 돌고는 있지만 **운영의 그것이 아니다** (가짜·스텁 주소·개발용 엔진) |
| `unverified` | 설정은 됐는데 성공 기록이 없다 |
| `not-configured` | 아직 붙이지 않았다 — **실패가 아니다** |
| `invalid` | 설정이 잘못됐다 |

**하나라도 `verified`가 아니면 `ready`는 false입니다** — 운영 전환에 부분 점수는
없습니다. 스텁 하나가 남아 있으면 그 경로의 결과는 여전히 사실이 아닙니다.

특히 `OPENAI_BASE_URL`·`ANTHROPIC_BASE_URL`을 봅니다. **우리 코드는 이 값을
읽지 않지만 공식 SDK가 읽습니다** — 우리가 모르는 사이에 상대가 바뀔 수 있는
창구입니다.

**두 화면이 다른 말을 하지 않도록** 연결 순서 판정도 같은 기준을 따르게
고쳤습니다: 엔드포인트가 공식이 아니면 `connected`가 아니라 `unverified`입니다
(실패로 부르지는 않습니다 — 스텁을 쓰는 것은 잘못이 아니고, 다만 연결의 증거가
아닐 뿐입니다).

**5. Amazon S3 운영 전환 (지시 5)**

전환 절차는 이미 `s3-migration.md`에 있었습니다. 이번에 추가한 것은 **어중간한
전환을 기계가 잡는 것**입니다.

- 주소는 Amazon인데 **자격 증명이 비었거나 `minioadmin`** → `invalid`
  (이 상태의 인증 실패는 "S3 장애"처럼 보입니다)
- **이미지 버킷과 백업 버킷이 같음** → `invalid` (결정 1701-②)
- 버킷에 닿지 못함 → `invalid` (IAM `s3:ListBucket`)
- 접근 점검 결과가 없음 → `unverified` (설정과 접근 가능은 다릅니다)
- `S3_ENDPOINT` 미설정 → `not-configured` (**미구성이며 실패가 아닙니다**)

**6. GitHub Actions 운영 검증 (지시 6) — 이번 TASK에서 가장 큰 발견**

워크플로 **파일**과 최근 **실행 결과**를 따로 판정합니다. 적혀 있는 것과 초록으로

**이 저장소의 CI는 13회 실행이 전부 실패하고 있었습니다.** 원인은 `pnpm test`에
web e2e가 들어 있는데 **러너에 Playwright 브라우저가 없어** 테스트 게이트가 통째로

왔습니다. **로컬에서만 통과하는 게이트는 게이트가 아닙니다.**

고친 것:

1. **Playwright 브라우저 설치 단계 추가** — 실패의 직접 원인
2. **TypeScript 게이트 추가** — CTO가 매 TASK 요구하는 게이트인데 워크플로에

   6곳 `tsc --noEmit`)

판정 쪽도 고쳤습니다. **실행 이력이 없으면 `unknown`입니다** — "실패한 적이
없다"와 "한 번도 안 돌았다"를 같은 초록으로 보여 주면, 아무도 CI를 켜지 않은
저장소가 가장 건강해 보입니다. `GITHUB_REPOSITORY` 미설정도 마찬가지로 모르는
것으로 둡니다.

## 8. 리스크·기술 부채

1. **실 자격 증명이 없어 지시 4·5의 "운영 검증"을 끝내지 못했습니다.** 이번에
   만든 것은 **전환이 아니라 전환을 판정하는 장치**입니다. 그 장치는 지금
   `ready: false`라고 말하고 있고, 그것이 사실입니다. 자격 증명이 들어오면 같은
   판정이 그대로 `verified`로 바뀝니다 (CTO_REQUEST #67 ①)
2. **CI 소요가 4분입니다** — 대부분이 web e2e(2분 33초)입니다. 테스트가 늘면
   더 길어집니다. 지금은 문제가 아니지만, 병렬 job 분리가 필요해지는 시점이
   옵니다
3. **공지 형식은 여전히 우리가 정한 계약입니다** — `acos`·`flat` 둘 다 JSON
   전제입니다. 실제 Provider의 가격 페이지는 HTML이고, 누군가 그것을 옮겨 주는
   것을 전제합니다
4. **공지가 밝힌 발효 시각을 자동으로 예약하지 않습니다**(#66 ② 미결)
5. **최종 승인자는 "다른 ADMIN"이면 누구나** 됩니다(#66 ③ 미결)
6. **Live Verification은 CI에서 돌지 않습니다** — 실 자격 증명이 필요하고 매
   푸시마다 과금됩니다. 계약 스텁으로 라이브 경로만 돌리는 선택지가 있습니다
   (#67 ④)
7. **감지는 OCR 단가만 기록으로 제안합니다** — LLM은 입력·출력 단가를 기록에서
   가를 수 없습니다(공지 대조는 LLM도 제안을 만듭니다)
8. **실패한 호출의 과금·무료 구간·환율은 여전히 우리 집계 밖입니다**
9. **운영 저장소가 아직 S3가 아닙니다** · **백업 성능 기준은 개발 규모에서만
   검증**(1901-④ 대기)
10. **디스크 할당량이 빠듯합니다** — 검증 중 여유가 1GB 수준입니다
