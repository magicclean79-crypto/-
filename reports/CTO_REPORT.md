## 3. 변경 사항 (이번 보고 주기)

### TASK-2101 — Enterprise Operational Automation

CTO 결정 2001-①~⑤가 이번 TASK의 범위였습니다.

TASK-2001은 **판정을 만들었습니다.** 이번 TASK는 그 판정이 **누가 누르지
않아도** 유지되게 합니다. 규칙은 있는데 아무도 실행하지 않으면 규칙이 없는
것과 같습니다 — 원격 대조 버튼이 그 상태였습니다.

**1. 사슬 관측 창 설정 (결정 2001-①)**

`BACKUP_CHAIN_WINDOW_HOURS`로 설정하고 기본은 24시간입니다.
**최소는 백업 간격의 4배**입니다.

| 상황 | 결과 |
| --- | --- |
| 설정 없음 · 최소 이상 | 24시간 (`default`) |
| 설정값 ≥ 간격 × 4 | 그대로 (`env`) |
| 설정값 < 간격 × 4 | **간격 × 4로 올림** (`clamped`) |
| 기본 24시간 < 간격 × 4 (예: 일 1회 백업) | **96시간으로 올림** |
| 해석 불가 · 음수 | 기본값으로 되돌림 |

창이 간격의 4배도 안 되면 창 안에 백업이 서너 개뿐이라 **한 번만 걸러도
판정이 뒤집힙니다.** 표본이 없는 판정은 판정이 아니라 잡음입니다.

**설정을 거절하고 판정을 멈추는 대신, 판정할 수 있는 창으로 올리고 올렸다는
사실을 화면에 적습니다.** 조용히 다른 값으로 도는 것이 가장 나쁩니다.

**2. 원격 대조 주 1회 자동 (결정 2001-②)**

예약 점검 `remote-verify`를 신설했습니다. **마지막 백업 1건만** 내려받아
SHA-256을 대조합니다.

- `PRODUCTION_ONLY_JOBS`로 **운영에서만 기본 켜짐**입니다 — 개발·테스트가
  전송 비용을 낼 이유가 없고, 개발 저장소에는 대조할 원격 사본도 없습니다.
  다만 환경변수로 명시하면 스테이징에서도 켤 수 있습니다.
- **결과를 남깁니다** (`backup_runs.remoteCheckedAt` · `remoteVerdict`).
  남기지 않으면 자동 대조를 돌려도 화면은 계속 "확인하지 않았습니다"라고
  말합니다 — 자동화를 넣은 의미가 없습니다.
- **화면과 경보는 기록을 읽습니다.** 조회할 때마다 내려받으면 화면을 여는
  것만으로 돈이 나갑니다.
- **주기의 2배를 넘긴 성공은 통과로 두지 않습니다** — 예약이 두 번 걸렀다면
  그때의 `ok`는 지금의 사실이 아닙니다. 반대로 **실패는 낡아도 실패입니다**
  — 시간이 지난다고 사본이 돌아오지 않습니다.

**3. `_major_` 파일명 규칙 + CI 교차 검증 (결정 2001-③)**

매니페스트를 유지하면서 파일명 규칙을 더했습니다. **둘의 합집합**을 major로
봅니다.

둘을 함께 두는 이유는 서로 다른 실수를 막기 때문입니다 — 매니페스트는 **잊기
쉽고**(파일을 만들고 목록에 넣는 것을 잊습니다), 파일명은 **되돌리기
쉽습니다**(이름을 바꾸면 지정이 사라집니다).

`pnpm check:major-migrations`가 어긋남을 잡습니다.

| 상황 | 종료 코드 |
| --- | --- |
| 일치 | 0 |
| 파일명이 `_major_`인데 매니페스트에 없음 | **1** |
| 매니페스트에 있는데 마이그레이션이 없음 | **1** |
| 읽지 못함 | **2** (판정 불가 — 통과로 처리하지 않습니다) |

매니페스트에만 있고 규칙을 안 따르는 것은 오류가 아닙니다 — 이름을 소급해
바꾸면 `_prisma_migrations`와 어긋납니다.

`.github/workflows/ci.yml`을 신설해 **build 뒤에** 돌립니다(검증 로직이
`@acos/core`에 있으므로).

**4. 재기동 후 확인 절차 (결정 2001-④)**

기동 시 1회 정책을 **유지**하는 대신, 결과를 남깁니다.

| `registered` | 뜻 |
| --- | --- |
| `true` | 요구가 새로 등록됨 |
| `false` | 등록할 것이 없거나 이미 미해소 요구가 있음 |
| **`null`** | **확인하지 못함** — "등록할 것이 없었다"가 아님 |

`GET /ops/readiness` → `enterprise.drill.autoRegistration`으로 노출하고
화면에도 칸을 두었습니다. **로그를 뒤지게 만들면 아무도 확인하지 않습니다.**
Runbook에 3단계 확인 절차를 넣었습니다.

**5. Amazon S3 운영 전환 계획 (결정 2001-⑤)**

`docs/operations/s3-migration.md`를 썼습니다 — 버킷 구성 · IAM 최소 권한 ·
이관 · 확인 · 되돌리기 · 남는 일.

**핵심은 저장소를 바꾸는 것이 아니라 `s3:GetBucketVersioning` ·
`s3:GetReplicationConfiguration` 조회 권한을 빠뜨리지 않는 것**입니다. 권한이
없으면 전환해도 보호 상태가 `직접 확인`으로 남아, 바꾼 의미의 절반이
사라집니다. 전환 완료 판정을 네 항목으로 못 박았습니다.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 판정을 예약과 기록에 얹는다**:

```
BACKUP_CHAIN_WINDOW_HOURS ─▶ resolveChainWindowMs(raw, intervalMs)
                               ├─ 간격 × 4 미만 → clamped (올렸다고 말한다)
                               └─ windowMs ─▶ backupHistorySince ─▶ judgeBackupChain

schedule: remote-verify (운영만, 7일)
   └─▶ verifyRemoteCopy() ─▶ S3 GET ─▶ SHA-256
          └─▶ backup_runs.remoteCheckedAt/remoteVerdict   ← 결과가 남는다
                 └─▶ judgeRecordedRemoteIntegrity ─┬─▶ readiness  (다시 안 받는다)
                                                   └─▶ watchdog 경보

major-migrations.json ─┬─▶ crossCheckMajorMigrations ─┬─▶ 기동 시 자동 등록
migrations/*_major_*  ─┘   (CI: exit 0/1/2)          └─▶ lastAutoRegistration
                                                          └─▶ readiness (재기동 확인)
```

① **비용이 드는 확인을 예약으로 옮기되, 결과를 남겨 조회는 공짜로 만들었습니다.**
   이것이 이번 TASK의 중심 구조입니다.
② **설정을 거절하지 않고 고쳐서 쓰되, 고쳤다고 말합니다** — 조용히 다른 값으로
   도는 것이 가장 나쁩니다.
③ **지정하는 길을 둘로 늘리고 어긋남을 CI로 막았습니다** — 길이 하나면 그
   길을 잊었을 때 아무 일도 일어나지 않습니다.
④ **자동화의 결과를 사람이 볼 자리에 두었습니다** — 기동 시 1회 정책을
   유지하기로 한 이상, 확인은 절차가 되어야 합니다.

**유지되는 핵심 결정**: Alert 정책 4종(1302-①) · 보관 90일·삭제 금지
(1302-④·1501-③) · 자동 폴백 없음(1401-①) · 로컬 시각 일 1회(1501-①) ·
Redis 장애 시 LLM 계속(1501-②) · 복원 대상 강제 분리(1601-②) ·
백업 1시간 간격(1701-①) · 버킷 분리(1701-②) · Versioning 운영 필수(1701-③) ·
리허설 분기 1회(1701-⑤) · 성능 기준 유지·자동 간격 변경 없음(1801-①) ·
리허설은 배포 게이트 아님(1801-②) · 요구 삭제 금지(1901-②) ·
중복 등록 금지(1901-⑤) · `/ops/*` ADMIN 전용

| --- | --- | --- |

메모리로 처리합니다. 자동 등록 결과를 DB에 남기지 않은 이유는 **그것이 이
프로세스의 기동 사실**이기 때문입니다 — 여러 인스턴스가 각각 자기 기동을
보고해야 합니다.

## 8. 리스크·기술 부채

1. **2101 해석 미확인** — 대조 대상 범위·창 상향의 강도·CI 게이트 위치
   (CTO_REQUEST #54)
2. **대조는 마지막 1건만 봅니다** — 그 앞의 원격 사본이 사라져도 알 수
   없습니다. 비용과 맞바꾼 선택입니다(#54 ①)
3. **창을 조용히 올립니다** — 화면에는 적지만 **경보하지는 않습니다.**
   설정과 실제가 다른 상태가 지속될 수 있습니다(#54 ②)
4. **CI 워크플로가 이 저장소에서 실행된 적은 없습니다** — 스크립트 자체는
   3경로를 실측했으나, GitHub Actions 실행은 확인하지 못했습니다(#54 ③)
5. **`remote-verify`는 분산 잠금을 잡습니다** — 여러 인스턴스에서 한 번만
   돕니다. 잠금을 못 잡으면 그 주는 건너뜁니다(설계대로이나, 두 주 연속이면
   낡음 판정으로 드러납니다)
6. **운영 저장소가 아직 S3가 아닙니다** — 계획은 섰고 체크리스트에서 **실패**로
   드러납니다. Sprint 21 안에 전환하는 것이 목표입니다(결정 2001-⑤)
7. **백업 성능 기준은 여전히 개발 규모에서만 검증됐습니다** — 10GB 신호는
   아직 울려 본 적이 없습니다
8. **복원 검증은 테이블 수만 봅니다** — 행 수·제약까지 보지 않습니다
9. **실 Provider 스모크는 여전히 미검증** — 샌드박스 차단 + 과금
