## 3. 변경 사항 (이번 보고 주기)

### TASK-1202 — Production Readiness & Deployment

지시 7항목 전부 이행. 설계의 축은 **"문서로만 있는 체크리스트는 지켜졌는지
확인할 수 없다"** 는 것이다. 기계가 판정할 수 있는 항목은 전부 자동화하고,
사람이 봐야 하는 것만 정직하게 "직접 확인"으로 남겼다.

**1. Environment Validation** — 환경변수 선언(`env-spec.ts`)을 **단일 원천**으로
두고 검증·대시보드·런북이 같은 선언을 쓴다. 설정이 코드·문서·런북 세 곳에
흩어지면 반드시 어긋나기 때문이다(Provider Registry와 같은 결).

| 심각도 | 기준 |
| --- | --- |
| `error` | 운영 필수 항목 누락 **또는 형식 오류**(형식 오류는 환경 무관 — 잘못된 값은 어디서도 동작하지 않는다) |
| `warning` | 운영 권고 위반 — mock Provider, 예산 미설정, `AUTH_COOKIE_SECURE` 꺼짐, `WEB_URL`이 localhost 등 |

**2. Startup Validation** — 기동 시 검증하고 **운영에서 오류가 있으면
기동하지 않는다**(exit 1). 잘못된 설정으로 뜬 서버는 조용히 오작동하다가 더
큰 사고를 만든다. 개발에서는 같은 문제를 경고로만 남기고 기동한다 — mock
구성이 정상이기 때문이다.

**3~4. Deployment Checklist & Configuration Verification**

| 항목 | 판정 | 배포 차단 |
| --- | --- | --- |
| 환경변수 검증 / DB 연결 / 마이그레이션 / 저장소 / 관리자 계정 | 자동 | ✅ |
| 실제 Provider 연결 | 자동 (운영에서 mock만이면 차단) | 운영만 |
| 비용 예산 · Failover 우선순위 | 자동 (경고) | ✗ |
| 실 Provider 스모크 · DB 백업 확인 | **직접 확인** | ✗ |

마이그레이션은 확인할 수 없으면 통과가 아니라 **"직접 확인"** 으로 둔다 —
모르는 것을 통과로 처리하지 않는다. 설정 현황에서 **비밀 값은 설정 여부만**
노출한다.

**5. Health Dashboard** — 웹 `/admin/health`: 배포 가능 여부·차단 사유·
체크리스트·구성 요소·환경 오류/권고·설정 현황. 구성 요소 점검은 **서로
독립적으로 실패**한다 — 저장소가 죽었다고 DB 상태까지 못 보게 되면 장애
대응이 어려워진다.

**6~7. Production Runbook & Recovery Guide** — `docs/operations/`에
배포 절차와 **증상별 복구 절차**(기동 실패·DB·저장소·Provider·예산·실험·
설정 미반영·롤백·사고 후 정리)를 작성했다.

**구현 중 발견해 고친 표시 결함**: 개발 환경에서 예산·Failover 미설정 항목이
상태는 `통과`인데 설명은 "비용 폭주를 막을 상한이 없습니다"·"단일 Provider
장애가 곧 서비스 중단입니다"였다. **상태와 설명이 정면으로 모순**돼 읽는
사람이 무엇을 해야 할지 알 수 없다. 환경별 문구로 분리하고 회귀 테스트를 남겼다.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 운영 판정 계층 추가**:

```
env-spec.ts (선언 단일 원천)
   ├─▶ validateEnvironment ─▶ 기동 검증 (운영 오류 → 기동 차단)
   │                        └▶ Health Dashboard 환경 오류/권고
   └─▶ describeEnvironment ─▶ 설정 현황 (비밀은 여부만)

실제 상태 (DB · 저장소 · 마이그레이션 · Provider · 관리자)
   └─▶ buildDeploymentChecklist ─▶ 배포 가능 여부 + 차단 사유
                                 └▶ 자동 판정 불가 항목은 manual
```

① 선언이 **단일 원천**이라 검증·화면·런북이 어긋나지 않는다. ② 판정 로직이
**core 순수 로직**이라 저장소 없이 경계 조건까지 테스트로 고정된다.
③ 구성 요소 점검이 **독립적으로 실패**해 장애 시 정보가 사라지지 않는다.
④ 모르는 것(마이그레이션 확인 불가)을 **통과로 처리하지 않는다**.

**유지되는 핵심 결정**: Code-first 설정 · 설정 우선순위(1201 승인 ①) ·
TTL 전파(1201 승인 ②) · Override 수동 해제(1201 승인 ④) · `/admin/*` ADMIN
전용(1201 승인 ⑤) · 단일 관문 · 미설정 시 기존 동작

**현황**: 모노레포(web·api·core/shared/agents/ui), 마이그레이션 25건
(이번 TASK 스키마 변경 없음), drift 없음

## 8. 리스크·기술 부채

1. **1202 해석 미확인** — 기동 차단 정책·필수 항목 목록·수동 항목 처리

2. **기동 차단의 양날** — 운영에서 설정 누락 시 서버가 아예 뜨지 않는다.
   의도한 동작이나, 배포 파이프라인이 이를 재시도로 오해하면 롤백이 늦어질 수
   있다(#44 ①)

4. **마이그레이션 확인은 `_prisma_migrations` 직접 조회** — Prisma 내부
   테이블에 의존하므로 Prisma major 업그레이드 시 확인이 필요하다
5. **백업·복구 절차는 문서만** — 실제 백업 도구·스케줄은 인프라 영역이라
   런북에 절차만 적었고 자동화하지 않았다
6. **실키 스모크·Rate Limit 인메모리·건강 상태 인스턴스별 학습** — 기존 부채
