## 3. 변경 사항 (이번 보고 주기)

### TASK-1401 — Production Operations Platform

지시 9항목 전부 이행. 이번 TASK는 **지난 보고에서 스스로 올린 부채 두 건을
갚는 것**이다. TASK-1302는 경보를 만들었지만 (a) 예약 점검이 인스턴스마다
중복 실행됐고 (b) 알림이 한 번 실패하면 **아무도 모르는 채로 끝났다**.

**1~3. Distributed Scheduler / Leader Election / Distributed Lock**
(CTO 결정 1302-②)

예약 실행은 **잠금을 잡은 인스턴스만** 수행한다. 수동 실행은 사람이 지금
확인하려는 것이므로 잠금을 요구하지 않는다.

| 항목 | 값 |
| --- | --- |
| 저장소 | Redis (`REDIS_URL`) — 미설정 시 단일 인스턴스 모드 |
| 잠금 이름 | `acos:lock:scheduler:<job>` |
| 임차 수명 | `OPS_LOCK_TTL_MS` (기본 30초) |
| 갱신 시점 | 남은 수명이 TTL의 1/3 이하 |

분산 락은 시계와 만료가 얽혀 **틀리기 쉬운 영역**이라, 판정만 core 순수
로직으로 떼어 냈다. 그 판정에 담긴 것들:

- **임차는 반드시 만료된다.** 리더가 죽으면 락이 영원히 잠기는 것이 가장 나쁜
  실패다 — TTL 없는 락은 쓰지 않는다.
- **만료 직전이 아니라 미리 갱신한다.** 만료 직전 갱신은 네트워크 지연 한 번에
  리더십을 잃는다.
- **소유자만 갱신·해제한다.** Lua 스크립트로 값을 비교한 뒤에만 바꾼다 —
  비교 없이 지우면 남의 임차를 해제해 **리더가 둘이 된다**.
- **Redis가 끊기면 잠그지 못한 것으로 본다.** 모르는 채 "잡았다"고 하면 중복
  실행이 조용히 일어난다.
- 단일 인스턴스 모드를 **숨기지 않는다** — API와 화면에 그대로 드러낸다.
  다중 인스턴스인데 단일 모드로 돌고 있으면 그것이 바로 사고다.

**4·7~9. Notification Center — Slack / Email / Webhook Retry**

| 채널 | 설정 | 최소 심각도 | 해소 알림 |
| --- | --- | --- | --- |
| Slack | `ALERT_SLACK_WEBHOOK_URL` | `ALERT_SLACK_MIN_LEVEL` | `ALERT_SLACK_RESOLVED` |
| Email | `SMTP_HOST` + `ALERT_EMAIL_TO` | `ALERT_EMAIL_MIN_LEVEL` | `ALERT_EMAIL_RESOLVED` |
| Webhook | `ALERT_WEBHOOK_URL` | `ALERT_WEBHOOK_MIN_LEVEL` | `ALERT_WEBHOOK_RESOLVED` |

- **채널 하나가 죽어도 나머지는 보낸다** — 알림 체계가 단일 장애점이 되면 안 된다.
- **심각도로 채널을 고를 수 있다** — 모든 warning을 밤중에 슬랙으로 받으면
  사람이 알림을 끈다. 해소 알림은 심각도와 **별도 스위치**다("critical만
  받겠다"는 사람도 해소는 받고 싶을 수 있고, 그 반대도 있다).
- **재시도**: 지수 백오프(1s→2s→4s, 상한 30초), 최대 4회(최초 포함).
  **4xx는 재시도하지 않는다**(429 제외) — 잘못된 URL·인증 실패는 같은 요청을
  다시 보내도 같은 답이 온다.
- **모든 시도 결과를 남긴다**(`notification_deliveries`) — 채널·횟수·마지막
  오류. "왜 아무도 못 받았는가"를 추적할 수 있어야 한다.
- **주소는 어떤 응답에도 담지 않는다** — 웹훅 URL·수신자도 비밀이다.

**5~6. Alert History / Archive** (CTO 결정 1302-④)

**삭제하지 않는다.** 해소 후 90일(`ALERT_ARCHIVE_AFTER_DAYS`)이 지나면
`ARCHIVED`로 옮겨 현황에서 비켜 두되 이력에는 남긴다. 보관과 삭제를 구분하는
이유는 분명하다 — 삭제는 되돌릴 수 없고, "그때 그 경보가 있었나?"를 나중에
확인할 방법을 영원히 없앤다.

- **활성 경보는 절대 보관하지 않는다** — 문제가 있는데 화면에서 사라지면 사고다.
- **해소 시각을 모르면 건드리지 않는다** — 유예가 지났는지 알 수 없다.
- 이력 요약에 **평균 해소 시간**을 넣었다. 경보가 많은 것보다 **오래 방치되는
  것**이 더 나쁜 신호인데, 건수만 세면 그게 안 보인다.

**웹 `/admin/production` 확장** — 채널 구성(무엇이 무엇을 받는지) · 예약 조율
(분산/단일 · 점검별 리더) · 전송 시도 이력(실패 건수) · "보관 정리" 버튼.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 조율 계층과 전달 계층**:

```
                    ┌─ decideLease / ownsLease (core, 순수)
DistributedLock ────┤
 (Redis, Lua CAS)   └─ 미설정 → 단일 인스턴스 모드 (사실을 노출)
        │
        ▼ 예약 실행만 게이트 (수동 실행은 통과)
ScheduledChecks ──▶ detect*Alerts ──▶ reconcileAlerts (종류별 쿨다운)
                                            │
                                     AlertService
                                            │
                          ┌─────────────────┴──────────────┐
                   NotificationCenter                  alerts 테이블
              (채널 선택 → 재시도 → 이력)          (ACTIVE/RESOLVED/ARCHIVED)
                          │
              slack · email · webhook   +   notification_deliveries
```

① 잠금·재시도·보관 **판정이 전부 core 순수 로직**이라 Redis·네트워크·시계 없이
테스트로 고정된다. ② **기존 동작이 기본값**이다 — `REDIS_URL`이 없으면 TASK-1302와
똑같이 돈다(회귀 없음). ③ **모르는 것을 통과로 처리하지 않는다** — Redis 장애 시
잠금 실패로 간주, 해소 시각 미상은 보관 제외. ④ **실패를 숨기지 않는다** —
전송 실패·단일 모드·리더 부재가 전부 화면에 드러난다.

**유지되는 핵심 결정**: Alert 정책 4종(1302-①) · Live Check 수동(1301-①) ·
진단 분리(1301-③) · Unpriced 비차단(1301-⑤) · Fail Fast(1202-①) ·
`/admin/*`·`/ops/*` ADMIN 전용(1201-⑤) · feature 4종(0601)

**현황**: 모노레포(web·api·core/shared/agents/ui), **마이그레이션 27건**,
drift 없음. 신규 의존성 2개(`ioredis`, `nodemailer`)

## 8. 리스크·기술 부채

1. **1401 해석 미확인** — Redis 의존 수위·채널 기본 정책·보관 자동화
   (CTO_REQUEST #47)
2. **Redis가 새로운 단일 장애점** — 다만 Redis가 죽으면 잠금을 못 잡아
   **예약 점검이 아예 돌지 않는다**(중복 실행보다는 안전하지만, 점검이 멈춘
   것을 알려 주는 장치는 없다). 이 상황을 감지할 경보가 필요하다(#47 ①)
3. **보관은 수동 트리거** — 예약 점검에 넣지 않았다. 결정 1302-④가 정책만
   지시했고 실행 주기는 지시하지 않아 임의로 정하지 않았다(#47 ③)
4. **메일 경로는 실 SMTP로 검증하지 못했다** — 샌드박스에 SMTP 서버가 없어
   Slack·Webhook만 실전송으로 확인했다. 메일은 단위 테스트(본문 생성)와 배선까지
   확인했고, 실 발송은 운영/스테이징 확인 항목으로 남는다
5. **재시도는 프로세스 안에서만 한다** — 인스턴스가 재시작하면 진행 중이던
   재시도는 사라진다. 큐 기반 전송은 넣지 않았다(#47 ②)
6. **인스턴스 종료 시 임차 반납은 정상 종료 경로만** — 강제 종료(SIGKILL)는
   TTL 만료를 기다린다(라이브에서 40초 인계 확인). 의도한 동작이다
7. **실키 스모크·백업 자동화** — 기존 부채
