## 3. 변경 사항 (이번 보고 주기)

### TASK-2601 — Enterprise Governance Operations Platform

CTO 결정 2501-①~⑤가 이번 TASK의 범위였습니다.

TASK-2501이 발행 게이트를 **켰습니다.** 이번에는 그것을 **켜기 전에 세어 보고,
켠 뒤에 정리하는** 도구를 붙였습니다. 규칙을 만드는 것과 규칙을 운영하는 것은
다른 일입니다.

**1. Governance Preflight Scan (결정 2501-①)**

규칙을 처음 켜면 **이미 `REVIEW`에 있던 콘텐츠들이 위반을 담고 있을 수 있고,
그러면 발행이 줄줄이 막힙니다.** 하나씩 눌러 보며 발견하는 방식으로는 언제
끝날지 알 수 없습니다.

> **상태를 바꾸지 않고, 자동으로 고치지 않고, 판정 기록도 남기지 않습니다.**
>
> 판정 기록을 남기지 않는 이유: 훑어본 것을 발행 시도로 기록하면 이력이
> 사실과 어긋납니다.
>
> 자동 수정을 만들지 않는 이유는 원격 사본 자동 복구를 만들지 않은 것
> (CTO 결정 2201-②)과 같습니다: 금지어를 기계가 지우면 문장이 무슨 뜻이
> 되는지 아무도 확인하지 않은 채 발행되고, 고지 문구를 기계가 덧붙이면
> 맥락과 무관한 자리에 붙습니다. 화면에도 "한 번에 고치기" 버튼을 두지
> 않았습니다 — 있으면 누군가는 누릅니다.

판정은 발행 게이트와 **같은 함수**(`ContentGovernanceService.judge`)를
부릅니다. 스캔이 "막힐 것"이라고 한 것이 눌렀을 때 통과하면 스캔을 볼 이유가
없습니다.

**2. 이미 나간 위반을 따로 센다**

| 값 | 뜻 | 해야 할 일 |
| --- | --- | --- |
| `blocked` | 아직 발행되지 않았고 위반 있음 | 발행 전에 고칩니다 |
| `publishedViolations` | **이미 발행됐는데 위반 있음** | **막을 수 없습니다** — 내리거나 고쳐 다시 발행합니다 |

**발행 게이트는 나가는 것을 막지만 이미 나간 것에는 아무 힘이 없습니다.**
섞어 세면 "위반 5건"이 무슨 뜻인지 알 수 없습니다. 문구도 목록도 **이미 나간
것을 먼저** 말합니다 — 막을 수 없는 것이 더 급합니다.

기본 스캔 범위는 아직 나가지 않은 것(`DRAFT`·`REVIEW`)이고,
`?status=PUBLISHED`로 이미 나간 것까지 봅니다.

**3. 조용히 자르지 않는다**

- `?limit`은 **목록만** 자릅니다 — **요약의 숫자는 자르기 전 전체**입니다.
  2건만 보여 주며 "위반 2건"이라고 하면 실제 건수를 아무도 모릅니다.
- 잘랐다는 사실과 생략 건수를 문구에 적습니다.
- 판정 대상 상한(500건)을 넘으면 `나머지는 검사하지 않았습니다`까지 밝힙니다 —
  목록을 자른 것과 **아예 보지 않은 것**은 다릅니다.
- 잘못된 `status`·`limit`은 **400**입니다. 조용히 기본값으로 되돌리면 운영자는
  자기가 준 값이 적용됐다고 믿습니다.

**4. 판정 기록 90일 보관 (결정 2501-⑤)**

경보(1302-④)·Dead Letter(1501-③)와 같은 정책입니다. **삭제하지 않습니다.**

- 기준은 **작성 시각**입니다 — 판정 기록에는 해소라는 개념이 없는 시점
  기록이므로 경보와 기준이 다릅니다. 그래서 작업 문구도 "해소 후"와
  "작성 후"를 **나누어** 적습니다(하나로 뭉치면 기준이 하나인 것처럼 읽힙니다).
- 예약 정리 작업(`alert-archive`)에 **편입**했습니다 — 새 작업을 만들지
  않았습니다. 같은 성격의 정리가 서로 다른 시각에 돌면 무엇이 남았는지
  흐려집니다.
- 이미 보관된 것은 다시 찍지 않습니다 — 찍으면 언제 보관했는지가 바뀝니다.
- 보관된 것도 `?includeArchived=1`로 **볼 수 있습니다** —
  볼 길이 없으면 보관이 사실상 삭제입니다.

**5. 하지 않기로 한 것을 테스트로 고정 (결정 2501-②③④)**

**하지 않기로 한 일은 코드에 흔적이 없어서 나중에 누가 되살려도 아무도
모릅니다.** 우회 플래그를 두지 않기로 한 것(결정 2201-③)을 고정한 것과 같은
이유로 `content-governance-boundary.spec.ts`를 두었습니다.

| 하지 않는 것 | 결정 | 고정 방법 |
| --- | --- | --- |
| 금지어 단어 경계·예외 목록 | 2501-② | `최고`가 `최고급`에 걸리는 것을 **정상 동작으로** 고정 · 코드에 `allowList`·`wordBoundary`·`new RegExp`가 없음을 소스 검사 |
| READY 전환 강제 | 2501-③ | READY 판정 모듈에 `throw`·`publishable`·`blocking`이 **없음**을 소스 검사 |
| 프로젝트·분류별 규칙 스코프 | 2501-④ | 판정 입력에 `scopeId`·`PROJECT`가 없음을 소스 검사 |
| 자동 수정 | 2501-① | `autoFix`류 출력이 없고 **왜 안 하는지가 주석으로** 남아 있음을 검사 |

`최고급`이 걸리는 것은 버그가 아니라 **넓게 걸고 사람이 판단한다**는 결정의
결과이고, 문서(§6)에 그렇게 적었습니다.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 규칙을 켜기 전과 켠 뒤**:

```
                      ┌─ GET …/governance          (1건 미리보기, TASK-2501)
ContentGovernance ────┼─ PATCH …/status → PUBLISHED (게이트, 기록 O)
   Service.judge      └─ GovernancePreflightService (여러 건 스캔, TASK-2601)
   (판정은 하나)             └─ 쓰기 없음 · 기록 없음 · 자동 수정 없음
                                 ├─ blocked            (막을 수 있다)
                                 └─ publishedViolations (이미 나갔다)

alert-archive (매일 04:00 로컬)
   ├─ 경보           보관 (해소 후 90일, 결정 1302-④)
   ├─ Dead Letter    보관 (해소 후 90일, 결정 1501-③)
   └─ 발행 판정 기록  보관 (**작성 후** 90일, 결정 2501-⑤)  ← TASK-2601
        └─ archivedAt 표시만 — 행은 남는다. ?includeArchived=1로 볼 수 있다
```

① **판정은 하나, 소비처는 셋입니다** — 미리보기·게이트·스캔이 같은 함수를
   부릅니다. 스캔이 다른 답을 내면 스캔을 볼 이유가 없습니다.
② **막을 수 있는 것과 이미 나간 것을 섞지 않습니다** — 게이트의 힘이 미치는
   범위를 숫자로 구분해야 무엇을 해야 할지가 정해집니다.
③ **읽기 전용 도구는 읽기만 합니다** — 쓰기 함수를 부르지 않음을 테스트로
   고정했습니다. "편의를 위해" 자동 수정이 붙는 것을 막는 유일한 방법입니다.
④ **보관 기준이 다르면 문구도 나눕니다** — 해소 후와 작성 후를 하나로 뭉치면
   기준이 하나인 것처럼 읽힙니다.
⑤ **정리 작업을 늘리지 않습니다** — 같은 성격의 정리가 서로 다른 시각에 돌면

   않았습니다(#59 ①)
3. **스캔은 사람이 눌러야 합니다** — 규칙이 바뀐 뒤 위반이 늘어도 아무도
   알려주지 않습니다. 예약 스캔·경보는 넣지 않았습니다(#59 ②)

   하고, 페이지네이션은 없습니다(#59 ③)

   500회입니다. 규칙은 스캔 한 번 안에서 바뀌지 않으므로 캐시할 수 있지만,
   넣지 않았습니다(#59 ④)
6. **보관된 기록은 목록 UI가 없습니다** — API로만 볼 수 있습니다
7. **필수 고지는 문구 포함 여부만 봅니다** — 위치·가독성은 보지 않습니다
8. **운영 저장소가 아직 S3가 아닙니다** — 전환은 운영 담당자 몫(결정 2101-④)
9. **백업 성능 기준은 여전히 개발 규모에서만 검증됐습니다**(결정 1901-④ 대기)
10. **실 Provider 스모크는 여전히 미검증** — 샌드박스 차단 + 과금
11. **GitHub Actions 실제 실행은 확인하지 못했습니다** — 워크플로 순서는
    테스트로 고정했습니다
