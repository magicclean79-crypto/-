## 3. 변경 사항 (이번 보고 주기)

### TASK-1901 — Enterprise Recovery Assurance

CTO 결정 1801-①~⑤가 이번 TASK의 범위였습니다. 주제는 **보증**입니다 —
관측만 하던 값에 기준을 붙이고, 판정이 미치지 않던 곳까지 같은 규칙을 넓히고,
달력에만 묶여 있던 리허설을 **변경에 반응하게** 만들었습니다.

**1. 백업 소요 시간 기준 (결정 1801-①)**

`backup_runs.durationMs`는 TASK-1601부터 기록되고 있었습니다. 이번에 한 일은
**그 값에 기준을 붙이는 것**뿐입니다 — 관측만 하고 판정하지 않으면 아무도
보지 않습니다.

| 소요 | 판정 | 경보 |
| --- | --- | --- |
| 2초 미만 | 정상 | 없음 |
| 2~10초 | 주의 | **없음** |
| 10초 초과 **연속 3회** | 실패 | warning |
| 30초 초과 (1회) | 실패 | **critical** |

- **연속 3회를 요구한 이유**: 한 번 느린 것은 흔합니다(디스크 경합, 작업
  겹침). 그때마다 경보하면 사람이 경보를 무시하게 됩니다.
- **30초는 한 번만 넘어도 심각**: 그 정도면 일시적 경합으로 설명되지 않습니다.
- **주의(2~10초)는 경보하지 않습니다** — 화면에는 드러나되 사람을 부르지
  않습니다. 부를 일이 아닌데 부르면 정작 불러야 할 때 오지 않습니다.
- **실패한 백업은 성능 판정에서 제외**합니다 — 실패는 백업 항목이 이미
  잡아내고, 실패까지 걸린 시간을 성능으로 세면 판정이 흐려집니다.
- **자동으로 간격을 바꾸지 않습니다.** 시스템이 스스로 백업을 드물게 만들면
  손실 구간이 조용히 늘어납니다 — 그 판단은 사람이 해야 합니다.

**2. 백업 버킷 보호 판정 (결정 1801-③)**

이미지 버킷과 **같은 규칙**으로 판정합니다. 판정 문구에 **어느 버킷
이야기인지**를 넣었습니다 — "버전 관리가 꺼져 있습니다"만 두 번 나오면 어느
쪽을 고쳐야 할지 알 수 없습니다.

**3. 운영 저장소 표준 = Amazon S3 (결정 1801-④)**

운영에서 `S3_ENDPOINT`가 `*.amazonaws.com`이 아니면 경고합니다. 개발 전용
저장소(MinIO·s3rver)는 버전 관리·복제 조회를 지원하지 않아, 그대로 운영에
쓰면 보호 상태를 **영영 `직접 확인`으로만** 보게 됩니다.

**4. 변경 후 즉시 추가 리허설 (결정 1801-⑤)**

**달력이 아니라 변경이 리허설을 부릅니다.** 90일 주기는 "아무것도 바뀌지
않았을 때"의 간격입니다.

| 사건 | `trigger` |
| --- | --- |
| 재해 복구 절차 변경 | `dr-change` |
| 데이터베이스 대규모 변경 | `db-major-change` |
| PITR 도입 | `pitr-adoption` |

- 등록되면 **기한이 남아 있어도 실패**입니다 — 마지막 리허설이 검증한 것은
  변경 이전의 시스템입니다.
- **성공한 리허설만 해소합니다** — 실패한 리허설은 "확인했다"가 아니라
  "안 되더라"는 뜻입니다.
- 판정과 경보의 **우선순위를 같게** 뒀습니다: 마지막 리허설 실패 → 변경 사건 →
  기한 초과.

**5. 배포 게이트에는 넣지 않음 (결정 1801-②)**

현행 유지를 확인하고, **배포 체크리스트에 리허설·백업 성능 항목이 없음을
회귀 테스트로 고정**했습니다. 확인만 하고 지나가면 다음에 누군가 무심코
넣어도 아무도 모릅니다.

**6. 스스로 발견해 고친 결함 3건**

| 결함 | 증상 | 조치 |
| --- | --- | --- |
| 경보 제목과 본문 불일치 | 판정은 실패를 먼저 보는데 경보는 변경 사건을 먼저 봐서, 제목 "변경 후 미수행" + 본문 "리허설 실패" 조합이 나올 수 있었음 | `lastFailed` 플래그로 구분 + 회귀 테스트 |
| 한국어 조사 오류 | 라이브에서 **"백업 버킷가"** 출력 — 라벨에 받침 유무를 가정할 수 없음 | 라벨 뒤 조사 제거(`—`로 분리) + 회귀 테스트 |
| 한국어 조사 오류 | 라이브에서 **"30.0초을 넘었습니다"** — 값 표기가 `초`/`ms`로 달라짐 | "보다 깁니다"로 변경 + 회귀 테스트 |

앞의 하나는 제가 이번에 만든 것이고, 뒤의 둘은 **라벨·수치를 문자열에 끼워
넣는 방식이 만든 구조적 문제**라 회귀 테스트로 막았습니다.

## 5. 아키텍처 변경 및 현황

**이번 주기 변경 — 기록에 기준을, 판정에 범위를**:

```
backup_runs.durationMs ─▶ judgeBackupPerformance
    (이미 있던 값)          ├─ 2초 미만        → pass
                            ├─ 2~10초          → warn  (경보 없음)
                            ├─ 10초 × 연속 3회 → fail  (warning)
                            └─ 30초 초과       → fail  (critical)
                                                   └─ 간격은 사람이 바꾼다

judgeStorageProtection(label) ─┬─▶ 이미지 버킷
                               └─▶ 백업 버킷  (결정 1801-③)

POST /ops/drills/require ─▶ drill_requirements ─▶ judgeRecoveryDrill
                                                    └─ 미해소 사건 > 주기
POST /ops/drills (ok=true) ─▶ satisfyRequirements
```

① **관측이 판정이 됐습니다** — 이미 재던 값에 경계를 붙였을 뿐, 새 계측은
   하지 않았습니다.
② **같은 판정 함수를 두 버킷에 재사용**하되 라벨로 구분했습니다.
③ **리허설이 시간이 아니라 변경에 반응**합니다.
④ **자동 조치를 넣지 않았습니다** — 간격 변경도, 배포 차단도 사람의 몫으로
   남겼습니다.

**유지되는 핵심 결정**: Alert 정책 4종(1302-①) · 보관 90일·삭제 금지
(1302-④·1501-③) · 자동 폴백 없음(1401-①) · 로컬 시각 일 1회(1501-①) ·
Redis 장애 시 LLM 계속(1501-②) · 복원 대상 강제 분리(1601-②) ·
백업 1시간 간격(1701-①) · 버킷 분리(1701-②) · Versioning 운영 필수(1701-③) ·
리허설 분기 1회(1701-⑤) · `/ops/*` ADMIN 전용

**현황**: 모노레포(web·api·core/shared/agents/ui), **마이그레이션 32건**,
drift 없음

## 6. 데이터 모델

**마이그레이션 32** (`20260730010000_drill_requirement`):

| 대상 | 변경 | 이유 |
| --- | --- | --- |
| `drill_requirements` (신규) | trigger · **description** · registeredBy · satisfiedAt · satisfiedBy | 달력이 아니라 변경이 리허설을 부른다 |

`description`을 필수로 둔 이유는 **다음 리허설이 무엇을 확인해야 하는지**가
거기 적히기 때문입니다. "DB가 바뀌었다"만으로는 리허설이 무엇을 다르게 해야
할지 알 수 없습니다.

백업 성능은 **새 컬럼 없이** 기존 `durationMs`로 판정합니다 — 이미 있는 값에
기준만 붙였습니다.

   없습니다(#52 ②)
4. **운영 저장소가 아직 S3가 아닙니다** — 표준은 정해졌지만 실제 전환은
   하지 않았습니다. 그때까지 보호 상태는 `직접 확인`으로 남습니다(#52 ③)
5. **백업 성능 기준은 개발 규모에서만 검증됐습니다** — 실제 소요가 225ms라
   2초·10초·30초 경계를 실측으로 넘겨 본 적이 없습니다(주입 테스트로만 확인)
6. **원격 사본 자동 검증은 여전히 유보** — 결정 1701-④
7. **복원 검증은 테이블 수만 봅니다** — 행 수·제약까지 보지 않습니다
8. **실 Provider 스모크는 여전히 미검증** — 샌드박스 차단 + 과금
