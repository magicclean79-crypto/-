## 1. 무슨 일이 있었는가

지시 3대로 `POST /ops/validation-run/execute`를 실제로 호출했습니다.

```
HTTP 403 Forbidden
검증을 시작할 수 없습니다 (3건).
```

거절 사유 셋:

| | 사유 |
| --- | --- |
| `target` | 검증 대상이 정해지지 않았습니다 — **어디에 돌릴지 모르는 채로 시작할 수 없습니다** |
| `people` | 사람이 줘야 끝나는 단계 **3건**: 실 Provider 자격 증명 주입 · 검증용 환경 확보 · 운영 호스트 목록 확인 |
| `blocked` | 앞 단계에 막힌 단계 **4건**: 스키마 적용 완료 · 기동 진단 실패 0건 · 실 호출 스모크 3종 통과 · 실 Provider 전환 검증 |

제품이 직접 말합니다:

> 강제로 여는 방법은 없습니다 — 막는 조건을 없애는 것이 유일한 길입니다.
> 준비되지 않은 채 돌리면 **스텁을 상대로 한 성공 기록이 남고, 그 기록은
> 나중에 실연결의 증거로 읽힙니다.**

**우회하지 않았습니다.** 지시 2가 명시한 그대로입니다 — mock으로 대체하면
`validation_runs`에 행은 생기지만, 그 행은 **거짓말**입니다.

## 2. Blocker 목록

### B-1. Provider Credential 없음 — **최상위 원인**

`LLM_PROVIDER=mock`. 나머지 Blocker 대부분이 여기서 파생됩니다.

**열두 스프린트째**입니다.

### B-2. Validation Environment 없음

검증 대상이 정해지지 않았습니다. 검증은 **실제 호출을 하고 돈을 씁니다** —
운영 DB에 대고 할 수 없습니다.

### B-3. Production Host Inventory 미확정

선언 2개 / **미선언 6개** / 안 보인 것 1개.

목록이 틀리면 **검증 대상 보호가 위험한 주소를 막는 것이 아니라 그냥
통과시킵니다.** 자동으로 채우지 않는 이유는, 채우면 스테이징까지 운영으로
올라가 **정작 검증 대상이 막히기** 때문입니다.

### B-4. 운영 저장소가 Amazon S3가 아님

`127.0.0.1:9000` (s3rver). 이 환경의 AWS 자격 증명은 **유효하지
않습니다**(`InvalidClientTokenId`, 읽기 전용으로 확인, 아무것도 만들지
않음).

### B-5. Backup Chain 18.4시간 공백

최근 24시간에 2/24회. **자격 증명 문제가 아니라 시간 문제**입니다 — 예약
백업이 도는 호스트가 24시간 이상 살아 있어야 합니다.

### B-6. Network Allowlist 부분 — `api.openai.com` 미도달

직접 확인 결과 Anthropic·Gemini·Vision·S3는 도달하고 **OpenAI만 연결
실패**입니다. 제품 판정은 "공식 주소 1곳에 모두 닿습니다"라고 하는데
**그 1곳은 Vision**이라, 판정만 보면 열려 있는 것처럼 읽힙니다.

## 4. 왜 이 상태로 v1.0.0을 붙이면 안 되는가

Go-Live 판정이 이 점을 정확히 말합니다:

> 실 Production Validation을 아직 한 번도 돌린 적이 없습니다 — **실패가
> 아니라 안 한 것입니다.** 이 상태에서 나머지 항목이 초록인 것은 준비가
> 끝났다는 뜻이 아니라 **아직 시작도 안 했다는 뜻**입니다 — 지금까지의
> 초록은 전부 스텁을 상대로 얻은 것입니다.

`v1.0.0`은 **"검증됐다"는 뜻의 번호**입니다. 검증하지 않은 것에 그 번호를
붙이면, 이 저장소가 쉰 스프린트 동안 지켜 온 **"모르는 것을 통과로
처리하지 않는다"** 를 제품 전체 수준에서 깨는 일이 됩니다.
