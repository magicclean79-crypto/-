## 0. 조사 방법과 접근 범위 — 무엇을 확인했고 무엇을 확인하지 못했는가

**접근 가능했다** — 사이트가 실제로 응답한다(추측이 아니다).

- 홈페이지(`http://magicclean791.godomall.com`), 개별 상품 상세페이지
  (`/goods/goods_view.php?goodsNo=...`)는 **로그인 없이** 접근 가능했다.
- 상품 **목록** 페이지(`/goods/goods_list.php?cateCd=...`)는 접근 시
  `member/login.php`로 강제 리다이렉트됐다 — **회원 로그인이 필요하다**
  (B2B 위탁배송 도매몰의 접근 제한). 로그인 자격 증명이 없어 목록 페이지의
  그리드 레이아웃(한 줄에 몇 개, 카드 디자인 등)은 **확인하지 못했다** —
  지어내지 않는다.
- 사용한 도구: (1) 텍스트 기반 웹 조회(HTML→마크다운 변환) (2) `curl`로 원본
  HTML·CSS 직접 다운로드해 실제 코드값(font-family·색상 hex·width 등) 확인
  (3) 상품 상세 이미지 6장을 실제로 다운로드해 **비전으로 직접 육안 확인**
  (사진 구도·배경·배지·텍스트를 이미지 안에서 직접 봤다 — AI가 요약한 텍스트만
  믿지 않았다).
- **실행하지 않은 것**: 실제 브라우저 렌더링(JS 실행)·스크린샷 캡처(이 세션에는
  Playwright 등 브라우저 자동화 도구가 없다). 반응형 여부는 CSS 소스(`viewport`
  meta 태그 존재 여부·`min-width` 값)로 판단했다 — 실제 모바일 기기 화면
  캡처는 하지 못했다.
- **표본 크기**: 상품 상세페이지 8건(청소용품 1·생활용품 3·주방용품 1·

  없다) — **이 표본이 전체를 대표한다고 단정하지 않는다.**

| 항목 | 값 | 근거 |
| --- | --- | --- |

**해석**: `<meta viewport>`가 없고 `min-width:1450px`인 고정폭 레이아웃이므로
이 사이트는 **모바일 반응형이 아니라 PC 전용(구형) 쇼핑몰 스킨**이다 —
godomall(고도몰) 플랫폼의 "pure" 스킨 기본값을 그대로 쓰고 있고(CSS 캐시
버스트 타임스탬프 `ts=1593501782` = 2020-06-30, 그 이후 스킨을 갱신한 흔적이
없다), 버튼 색상(`#e38bac` 핑크)도 이 스킨의 기본 팔레트로 보인다 —
`custom.css`가 비어 있어 **매직크린이 이 색을 의도적으로 브랜드 컬러로
고른 근거가 없다.** 즉 **이 사이트의 시각 스킨 자체는 "매직크린 고유
브랜드 디자인"이 아니라 "플랫폼 기본 스킨"** 이라는 것이 이번 조사의 핵심
발견이다 — 여기서 폰트 크기·핑크 버튼색 같은 스킨 값을 그대로 베끼면 안
되는 이유이기도 하다(그건 매직크린의 선택이 아니라 플랫폼의 기본값이다).

## 3. 상품 상세페이지 실제 섹션 순서 (원본 HTML의 `<h3>` 태그 원문, 순서 그대로)

```
1. [상품명]                    예: "운동화솔 색상랜덤"
2. 상품상세정보                 ← 판매자가 올린 상세 이미지(아래 §4)
3. 상품필수 정보                ← 전자상거래법 "상품정보제공고시" 표
4. 배송안내
5. 교환 및 반품안내
6. 환불안내
7. AS안내
8. 상품후기
9. 상품Q&A
```

가격·옵션·배송비는 상품명 바로 아래, "상품상세정보" 섹션보다 **먼저**
노출된다(정가 → 판매가/"사업자전용" → 배송비 → 이미지 갤러리·확대 →
SNS공유 → 위 9개 섹션). **리뷰·Q&A는 항상 맨 아래**다 — 신뢰 신호로 앞세우지
않는다(§7 IKEA/다이소 조사와 대비되는 지점, 아래 §6 참고).

## 4. "상품상세정보" 실제 내용 — 8건 조사에서 반복 관찰된 패턴

가장 중요한 발견이다: **"상세정보" 섹션은 대부분 사진 1장(간혹 배송정책
안내 이미지 1장 추가)뿐이고, 텍스트로 된 마케팅 카피·기능 설명·사용법
문단이 거의 없다.** 직접 다운로드해 육안으로 확인한 6장:

| 상품 (카테고리) | 상세 이미지 파일크기 | 실제로 본 것 |
| --- | --- | --- |
| 운동화솔 (청소용품) | 215KB | 4색 패키지 낱개 사진 + 브러시 클로즈업 인셋 원 |
| 폴리 미니 등받이의자 (생활용품) | 90KB | 파란 의자 단독 사진(흰 배경), 법정고시 스티커 부착 |
| 코멕스 아이스탱크 50L (주방용품) | 269KB | 아이스박스 단독 사진(흰 배경), 로고 각인 클로즈업 |
| 진로 차량용 방향제 (캠핑/차량 관련) | 124KB | 패키지 박스 사진 + 실제 차량 송풍구 장착 인셋 원 |
| 소변기 탈취패드 10P (욕실용품) | 26KB | 변기 일러스트 + 제품 낱개 배열 + "10P" 원형 배지 |
| 강화유리 뚜껑 34cm (주방용품) | 16KB | 뚜껑 단독 사진(흰 배경) + "34cm" 원형 배지 |

**공통 패턴 4가지** (6건 중 6건 모두):

1. **배경**: 전부 흰색/거의 흰색 배경 — 라이프스타일 연출 사진(방·주방에
   놓인 사진)이 하나도 없다. 순수 제품 사진이다.
2. **구도**: 3/4 각도 또는 정면, 제품이 프레임의 60~90%를 차지 — 근접·풀샷
   혼합이 아니라 "이거 하나면 다 보인다"는 단일 대표 컷.
3. **텍스트**: 이미지 안에 들어간 텍스트는 브랜드 워드마크(JINRO 등)나
   스펙 숫자(34cm, 10P) 뿐 — 설득형 카피(굵은 헤드라인 문구, 효능 나열)는
   6건 중 **0건**.
4. **보조 요소**(6건 중 4건에서 관찰): 작은 원형 인셋(사용 장면 클로즈업)
   또는 색상 원형 배지(규격 숫자) — 사진 전체를 뒤덮는 오버레이가 아니라
   구석에 작게.

**긴 스크롤형 상세페이지(사진→설명→사진→설명 반복, 여러 섹션으로 구성된
마케팅형 상세페이지)는 이번 표본 8건 중 단 1건도 없었다.** 이 시장조사
직전에 이미 확보한 `LIVING_GOODS_DESIGN_PRINCIPLES.md`(IKEA·다이소·지그재그
53건 조사)가 관찰한 "사진→캡션 반복", "리뷰 수 강조", "톤온톤 배경" 같은
정교한 상세페이지 관습은 **이 실제 운영 사이트에는 나타나지 않는다.**

## 5. 카테고리 간 비교 — 실제로 다른 것과 다르지 않은 것

- **페이지 골격(§3의 9개 섹션 순서, CSS 스킨)은 카테고리와 무관하게
  동일하다** — 플랫폼(고도몰) 스킨이 전체 사이트에 한 벌 적용되기
  때문이다. 청소용품이든 주방용품이든 상품정보고시 표 위치·리뷰 위치가
  달라지지 않는다.
- **실제로 카테고리마다 달랐던 것은 오직 "상세 이미지 자체의 내용"뿐이다**
  — 위 §4 표 참고. 예를 들어 욕실용품(소변기 탈취패드)은 "사용 대상
  기기(변기) 일러스트 + 수량 배지"를, 차량 관련 상품(방향제)은 "실제
  장착 위치 인셋"을 쓰는 식으로, **판매자가 그 제품을 가장 빨리 이해시킬
  수 있는 보조 요소 하나를 고른다**는 경향만 관찰됐다 — 카테고리별로
  강제된 레이아웃 규칙이 있는 게 아니라, 개별 판매자·상품 재량이다.
- **결론**: 이 실제 사이트에서는 "카테고리별 상세페이지 디자인 차이"라는
  것 자체가 **구조적으로 거의 없다**(플랫폼 스킨이 하나다). 대신
  "그 카테고리 제품을 설명하는 데 무엇이 유용한가"(치수 배지·사용 인셋·
  낱개 구성 배열)라는 **보조 정보 요소의 필요성**만 카테고리·제품 특성에
  따라 갈린다. T1-78이 요청한 "카테고리별 차이"는 이 사이트 자체에서는
  뚜렷하게 존재하지 않는다는 것이 정직한 결과다 — 있다고 지어내지 않는다.

## 6. 우리 시스템에 반영할 일반화된 규칙 — 그대로 베끼지 않고 전환한 것

## 8. 이미지 배치 규칙 — 검증된 Product Package·실제 제품 사진이 상세페이지에 어떻게 배치돼야 하는가

이번 조사(§4·§6 R1·R8)가 뒷받침하는, 이미 구현된 기존 규칙을 재확인한다
(새로 바꾼 것은 없다 — 코드가 이미 이 방향이다):

1. **Hero = 대표 썸네일(HERO 카테고리)** — 흰/중립 배경 단독 제품 사진 1장.
   실사이트 관찰(§4)과 일치.
2. **특징 카드 = FEATURE_HIGHLIGHT** — 사진 옆에 사실 기반 캡션 1줄. 실사이트는
   캡션 자체가 거의 없었지만(§4), 이는 "정보가 부족해서"이지 "캡션이
   나쁜 패턴이라서"가 아니다 — 우리는 검증된 Product Package(교차 검증 통과
   특징만, T1-23)가 있으므로 캡션을 넣는 것이 타당하다.
3. **사용 장면(USAGE_SCENE) → 디테일(DETAIL) → 구성품(COMPONENTS) → 기타(OTHER)** 순으로
   이어진다(`CATEGORY_ORDER`, 기존 구현). 실사이트의 "인셋 클로즈업으로 사용법·
   장착 위치를 보여준다"(§4, 방향제·운동화솔 사례)는 관찰이 이 순서(사용
   장면을 특징 다음, 디테일보다 앞)와 부합한다 — 순서를 바꿀 근거가 없다.
4. **OCR/라벨/포장/설명서 이미지(INFO)는 상세페이지 최종 배치에서 배제**된다 —
   `ImageGenService.assertNotInfoImage`로 이미 강제됨. 실사이트도 상세
   이미지에 라벨·설명서 사진을 그대로 쓰지 않고 정제된 단독 제품샷만
   썼다(§4) — 이미 채택한 방향과 일치, 변경 없음.
5. **법정고시성 스펙(specRows)은 사진과 분리된 텍스트 섹션**으로 — 실사이트의
   "상품필수 정보" 분리(§3)와 일치, 변경 없음.

## 10. 확인하지 못한 것 (추측하지 않고 남긴다)

- 상품 목록(카테고리) 페이지의 그리드 레이아웃 — 로그인 필요, 접근 못 함.
- 실제 브라우저 렌더링 시 모바일 화면이 어떻게 보이는지(레이아웃이 깨지는지,
  가로 스크롤이 생기는지 등) — JS 실행·스크린샷 도구가 이 세션에 없어
  실측하지 못했다. §2의 "PC 전용으로 추정"은 CSS 소스 근거이지 실제 화면
  캡처 근거가 아니다.
- letter-spacing의 실제 사용 여부 — 원본 CSS에 이 속성을 쓰는 규칙을
  찾지 못했다(없다는 것 자체가 발견이지만, "전혀 안 쓴다"고 100% 단정할
  만큼 CSS 전체를 다 읽지는 않았다 — 주요 파일 4개만 확인했다).
  `custom.css`가 비어 있어 커스텀 규칙은 없다고 판단했다.
- 전체 상품 수, 8건 표본 밖 상품들의 상세 이미지 스타일 분포(예: 8건보다
  더 공들인 상세페이지가 일부 상품에 존재할 가능성) — 로그인 없이 카탈로그
  전체를 순회할 방법이 없었다.
