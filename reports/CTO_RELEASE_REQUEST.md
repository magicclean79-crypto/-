## 결정 대기 (제출 당시)

### R-1. v1.0 정식 출시 여부 — **보류를 권고합니다**

- **현황**: 게이트는 전부 초록입니다(Build · TypeScript · ESLint ·
  Playwright · 전체 Test 2,960 · Live Verification 11/11 · CI 3 Job).
  그런데 **실 AI Provider를 상대로 한 번도 돌아 본 적이 없습니다** —
  `validation_runs`는 여전히 **0건**이고 `pnpm cutover`는 **활성화
  1/3**입니다.
- **저희 판단**: 지금 v1.0을 붙이면 **"검증됐다"는 뜻의 번호를 검증되지
  않은 것에 붙이는 일**이 됩니다. 이 저장소가 스프린트마다 지켜 온
  "모르는 것을 통과로 처리하지 않는다"를 제품 전체 수준에서 깨는
  선택입니다.
- **제안**: 두 단계로 나눕니다.
  - **지금 → `v1.0.0-rc.1`** (Release Candidate). 내부 사용자는 바로
    쓸 수 있습니다.
  - **넷이 준비된 뒤 → `v1.0.0`** (정식).
  코드는 이미 그 상태이며 **태그만 남았습니다.**
- **질문**: 이 두 단계 안을 승인하시겠습니까? 아니면 지금 정식 v1.0을
  붙이라고 지시하시겠습니까?
  - 정식을 지시하시면 그대로 하겠습니다. 다만 **무엇이 검증되지 않은
    채로 나가는지**는 `KNOWN_LIMITATIONS.md`에 그대로 남습니다.

### R-2. 넷의 준비 — **열한 스프린트째입니다**

- **현황**: Provider 자격 증명 · 네트워크 허용 목록 · 검증 환경 ·
  운영 호스트 목록. 이 넷이 없어 `POST /ops/validation-run/execute`는
  **403**이고, 정식 출시의 유일한 전제가 여기 걸려 있습니다.
- **저희가 할 수 있는 것은 없습니다.** TASK-4501에서 실행기를 만들어
  두었고, 넷이 오는 순간 경로 하나로 검증이 시작됩니다.
- **질문**: 이 넷을 **누가 언제까지** 준비할지 정해 주십시오. 날짜가
  정해지지 않으면 v1.1 계획도 그 앞에서 멈춥니다.

### R-3. 운영 준비 3건 — **지금 시작할 수 있습니다**

Production Readiness가 `recoverable: false`입니다. 세 가지가 fail이며,
**코드가 아니라 운영 절차**입니다:

| 항목 | 지금 | 해야 할 일 |
| --- | --- | --- |
| 백업 사슬 | 24시간에 1/24회 (**18시간 공백**) | 정해진 간격으로 돌리기 |
| 복원 검증 | 대상 DB 미구성 | `BACKUP_RESTORE_DB_URL` 지정 (**운영 DB 금지**) |
| 복구 리허설 | 대규모 DB 변경 후 미실시 | 1회 수행 |

- **질문**: 이 셋을 **v1.0 정식의 전제로 묶을지**, 아니면 출시 후 즉시
  처리할 항목으로 뺄지 정해 주십시오. 저희 권고는 **묶는 것**입니다 —
  복원해 보지 않은 백업은 백업이 아닙니다.

### R-4. 운영 저장소 전환 (s3rver → Amazon S3)

- **현황**: 개발용 s3rver입니다. 버전 관리·복제 상태를 **조회할 수
  없어** 보호 상태가 영영 "직접 확인"으로만 남습니다(결정 1801-④).
- **질문**: v1.0 정식 전에 전환할지 확인 부탁드립니다. 절차는
  `docs/operations/s3-migration.md`에 있습니다.

### R-5. Code Freeze의 범위 — 확인 부탁드립니다

- 이번 Sprint에서 **API 변경 금지**를 이유로 **H-1(실행 중 버전 노출)을
  고치지 않았습니다.** 기존 응답에 칸 하나를 더하는 일이지만, 규칙은
  규칙이라 손대지 않았습니다.
- 그런데 장애 때 **"지금 무엇이 떠 있는가"** 에 답하지 못하는 것은
  운영상 실질적인 불편입니다.
- **질문**: 이런 **추가만 하는 응답 확장**을 Freeze 예외로 둘지, 아니면
  v1.1까지 그대로 둘지 정해 주십시오.

### R-6. v1.1 우선순위 확인

자동 생성 · 7. 나머지 AI 경로 · 8. 요청 수 제한 확대
