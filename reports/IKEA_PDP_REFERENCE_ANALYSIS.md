# IKEA Korea 실제 PDP 38건 분석 — "하나의 템플릿 + 조건부 모듈" 레퍼런스

> 배경: "생활용품" 카테고리 워크플로우 실행 중 `args.category`가 문자열
> "undefined"로 잘못 전달되는 버그가 있었다(수정함, 아래 참고). 그 결과
> 조사 에이전트가 특정 카테고리를 지정받지 못해, 대신 "실제로 접근 가능한
> 개별 상품 상세페이지"라는 제약에만 집중해 **IKEA Korea 공식몰**
> (ikea.com/kr/ko — 서버렌더링이라 검색엔진에 개별 상품이 대량 색인되어
> 있어 접근이 확인됨)에서 소파·침대·조명·주방·수납 등 다양한 카테고리에
> 걸쳐 실제 상품 38건을 Playwright로 캡처하고 화면을 직접 봤다.

**의도한 조사는 아니었지만, 결과는 그 자체로 매우 가치 있다** — 우리가
최종적으로 만들려는 것("AI가 제품을 분석해 디자인 시스템에서 가장 적합한
레이아웃을 자동 선택")을 **IKEA가 실제 프로덕션에서 이미 하고 있는 사례**
이기 때문이다.

## 핵심 발견 — IKEA는 카테고리 무관 "단일 마스터 템플릿 + 조건부 모듈"

38건 전부가 거의 동일한 뼈대를 쓴다:

```
[앱/멤버십 가입 유도 배너]
[제품명 + 핵심 특징 불릿 2~4개(사진 아님, 텍스트 먼저)]
[색상/사이즈 옵션 선택]
[배송 가능 여부 확인 입력창]
[가격 + 수량 + 구매 버튼(강조 검정/블루)]
[탭: 개요 | 소재와 관리 | 리뷰]
[히어로 라이프스타일 사진 1장(+디자이너 이름)]  ← 사진은 여기서야 등장
[본문 설명 텍스트(소재/지속가능성 등)]
[고객 리뷰(평점+리뷰수, 낮아도 그대로 노출)]
[추천 액세서리 그리드]
[관련제품/추천제품 캐러셀]
[시리즈 확장 제품 안내]
[푸터]
```

**사진보다 텍스트(약속 불릿)+구매 버튼이 항상 먼저 나온다** — 38건 중
예외 없이 관찰됐다. "전환 우선형" 설계로, 비주얼 설득은 스크롤 하단으로
미룬다.

## 카테고리별로 달라지는 "조건부 모듈" (뼈대는 그대로, 이 부분만 바뀜)

| 제품 유형 | 뼈대에 추가되는 모듈 | 근거 사례 |
| --- | --- | --- |
| 아동용 가구(로프트베드 등) | **KC 안전인증 배지**, 소재 안전성 문구, 안전가드 관련 스토리텔링 | VITVAL 로프트베드: 가격 아래 KC 배지 노출 |
| 완구(봉제인형) | 안전 경고 문단(눈 부착 등)을 본문 중간에 명시적 삽입 | KRAMIG 소프트토이 |
| 조합형 가구(책상 등) | 정적 사진 + **동영상(재생버튼)**, 사이즈 선택 옵션 UI | LINNMON/KRILLE 책상 |
| 색상 옵션이 핵심인 제품 | **배경색 자체를 제품 컬러로** 재현(색 인지 강화) | LAGERGÅNG 모니터 조명(터쿼이즈 배경) |
| 조명류 | 가격을 페이지에서 가장 큰 글자로 강조, 짧은 사용 영상 | ISJAKT 플로어 조명 |
| 저가 소품 | 클로즈업 사용컷 + 교차판매 프로모션 서브섹션 | YTBERG LED 수납장 조명(₩9,900) |
| 스테디셀러(리뷰 압도적) | 리뷰 수를 신뢰 지표로 크게 노출(SLÄKT 1,077건 등) | 여러 사례 공통 |
| 옵션이 많은 제품(사이즈/구성) | "옵션 살펴보기" 서브섹션 추가 | SLÄKT, SVÄRTA |

## 스펙표 — 표 형태가 아니라 "아코디언 텍스트"

38건 중 표 형태로 즉시 노출되는 스펙표는 **하나도 없었다.** 치수/소재는
"소재와 관리" 탭이나 아코디언 링크로 접혀 있고, 기본 화면에는 사이즈
선택 버튼(예: "90x200cm")에 텍스트로만 잠깐 보인다. 이는 이번 시장조사의
다른 접근 가능 사이트들(지그재그·데코뷰 등)이 표 형태 스펙을 앞세우는
것과 **뚜렷한 차이**다 — IKEA는 "고르게 하고, 필요하면 펼쳐 보게" 하는
방식을 쓴다.

## 색상·타이포 — 절제된 시스템

전체 화이트 배경 + 블루/블랙 CTA 두 가지 색만 구조적으로 반복. 화려한
색은 **딱 한 곳**(제품 자체의 컬러 옵션을 배경색으로 쓰는 경우)에만
등장한다. 타이포도 제목/가격만 굵게 키우고 본문은 전부 작은 회색 —
"위계는 명확하되 화려하지 않다"가 IKEA 시스템의 원칙으로 보인다.

## 이 발견을 Template V1/디자인 시스템에 어떻게 반영할까 (제안, 결정 아님)

1. **"단일 뼈대 + 조건부 모듈" 아키텍처가 우리 목표(AI가 제품 특성에
   맞춰 레이아웃을 자동 선택)와 정확히 같은 개념**이다 — Template V1을
   여러 개의 고정 템플릿으로 나누기보다, "기본 뼈대 + 제품 특성별 모듈
   on/off"로 설계하는 것이 IKEA 사례로 검증된 방향일 수 있다.
2. 다만 IKEA는 **사진보다 텍스트/CTA를 먼저 배치**하는데, 이는 우리가
   지금까지 만든 Template V1(Hero 사진 먼저)과 반대다 — 매직크린
   베이스라인도 "사진+캡션" 중심이라, 이 부분은 시장(IKEA)과 우리 브랜드
   둘 다 사진 중심이므로 IKEA의 텍스트-우선 방식을 그대로 따라갈 필요는
   없어 보인다(카테고리별 조사가 더 필요한 지점).
3. 스펙표를 표 형태로 미리 보여주는 것은 IKEA보다 우리(및 다른 접근
   가능 사이트들)가 이미 더 친절한 방식일 수 있다 — 유지 후보.

## 버그 수정 기록

`args.category`가 워크플로우 실행 시 `"undefined"`(문자열)로 전달되는
문제를 확인했다 — 재현 원인은 명확히 특정하지 못했으나, 카테고리 값을
`args`로 전달하는 대신 **스크립트 문자열에 직접 하드코딩**하는 방식으로
바꿔 재실행한다(캐시 우회를 위해 새 실행). `ikea.com/kr/ko/p/`는 이번에
접근 가능함이 확인됐으므로, 앞으로 모든 카테고리 조사의 공통 시드
도메인으로 추가한다.
