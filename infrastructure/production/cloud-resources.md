두 버킷 모두 2026-08-06 생성(`TASK-5501`). 보호 설정은 제대로 켜져
있습니다.

### ⚠️ 백업 버킷이 비어 있습니다 — 원격 복제가 동작하지 않습니다

로컬 백업은 **정상입니다**:

```
/home/ec2-user/acos-data/backups/   *.dump 194개 · 총 8.9G
매시간 1회 · 최신 2026-11-09 01:31 · 1개당 약 49MB
보관 7일 (acos-prune-backups.timer, 매일 00:00 UTC)
```

그런데 **`BACKUP_OFFSITE`가 `.env`에 아예 없습니다.** `BACKUP_BUCKET`은
설정돼 있지만, 복제를 켜는 스위치가 없어 업로드가 일어나지 않습니다.
그래서 버킷 객체가 0개입니다.

**의미**: 백업이 **운영 DB와 같은 호스트에만** 있습니다. 그 호스트가
사라지면 **데이터와 백업이 함께 사라집니다.** 버킷은 이미 만들어져 있고
권한도 있으므로, 스위치 하나가 빠진 상태입니다.

조치(운영 호스트 `.env`에 1줄 추가 후 API 재시작):

```
BACKUP_OFFSITE=on
```

```bash
sudo systemctl restart acos-api
# 확인: 다음 백업(매시 31분) 후
aws s3 ls s3://detail-generator-backup-20260806 --recursive | tail -3
```

**이 세션에서는 실행하지 않았습니다** — 운영 설정 변경이고, 비용(S3 PUT·
저장)이 발생하며, 되돌릴 때 버킷 객체 정리가 필요합니다.

### 수명주기 규칙이 없습니다

버전 관리가 켜진 버킷에 수명주기 규칙이 없으면 **구버전이 영구히 쌓입니다.**
원격 복제를 켜면 1시간마다 49MB가 올라가므로(월 약 35GB) 비용이 계속
늘어납니다. 복제를 켤 때 보관 정책을 함께 정하기를 권합니다.

## 4. 저장소로 백업할 수 없는 것 — 사람이 콘솔에서 확인할 항목

조회 권한이 없거나 코드로 표현할 수 없어 **기록만 남깁니다.**

| | 항목 | 왜 필요한가 | 어디서 |
| --- | --- | --- | --- |
| 1 | **보안그룹 `launch-wizard-1` 인바운드 규칙** | 호스트 재생성 시 80/443·22를 다시 열어야 함 | EC2 콘솔 → 보안그룹 |
| 2 | **공인 IP가 Elastic IP인지** | 아니면 재시작 때 IP가 바뀌고 DNS가 깨짐 | EC2 콘솔 → 탄력적 IP |
| 3 | **Cloudflare DNS 레코드** | `magicclean79.com`·`www`·`api` → `3.39.9.111` A레코드. 프록시(주황구름) 여부도 | Cloudflare 대시보드 |
| 4 | **IAM 사용자 `detail-generator` 정책** | 재생성 시 같은 권한을 다시 부여 | IAM 콘솔 |
| 5 | **S3 버킷 정책·CORS** | 조회는 했으나 정책 본문은 미확인 | S3 콘솔 |
| 6 | **도메인 등록기관·만료일** | 도메인이 만료되면 전부 멈춤 | 등록기관 |

**2번이 특히 중요합니다.** 고정 IP가 아니면 인스턴스를 멈췄다 켜는 순간
DNS가 끊기고, 그 사실을 미리 알 방법이 없습니다.

- 보안그룹·DNS·IAM 정책의 **실제 내용**은 들어 있지 않습니다(§4).
